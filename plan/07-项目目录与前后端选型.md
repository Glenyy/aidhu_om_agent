# 07 项目目录与前后端选型

规划版本：v2.3｜日期：2026-10-05｜状态：待用户审阅

用户已确认：首版在个人电脑本地运行，通过浏览器上传 Excel、查看进度与结果、下载文件。以下技术组合和目录是建议提交的工程方案，尚未进入代码开发。

## 1. 建议技术组合

| 层 | 技术 | 本项目中的用途 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript | 页面、类型约束、可复用的结果和证据组件 |
| 构建 | Vite + pnpm | 根目录统一管理前端依赖，开发代理 /api、生成静态文件 |
| UI 组件 | Element Plus | 文件上传、表格、进度、筛选、详情抽屉 |
| 页面路由 | Vue Router | 新建、列表、详情三类页面 |
| HTTP 客户端 | Axios | 统一 API 调用、上传和错误处理 |
| 后端 API | Python 3.12 + FastAPI + Uvicorn | 上传预检、批次操作、状态查询、结果导出下载 |
| Agent 核心 | 普通 Python 固定流程 | V3 分析资料 → R1 检查答案，不引入额外 agent 框架 |
| 模型适配 | OpenAI 兼容 SDK | 复用当前服务协议，阶段模型可配置 |
| 数据校验 | Pydantic | 模型响应、业务类型和 API 数据校验 |
| Excel | openpyxl | 读输入，输出四表结果 |
| 持久化 | 标准库 SQLite | 批次、队列、阶段检查点和调用历史 |
| 后台执行 | 本项目独立串行 worker | 唯一消费任务，长时间模型调用与页面请求分离 |
| 验证工具 | pytest、Vitest、Playwright | 后端逻辑、关键前端逻辑、浏览器完整流程 |

当前旧项目 vue-admin 使用 Vue 3、Element Plus、Axios 和 Vue Router，因此这个前端组合有已有项目参考。新项目采用独立 Vite 工程，避免直接复制旧脚手架及其业务代码。

Vue 官方支持基于 Vite 的 TypeScript 项目；Vite 构建本身不替代类型检查，本项目增加 vue-tsc 检查命令。[Vue TypeScript 文档](https://vuejs.org/guide/typescript/overview.html)

Element Plus 提供本项目所需的上传和表格组件。[上传组件](https://element-plus.org/en-US/component/upload.html)、[表格组件](https://element-plus.org/en-US/component/table.html)

FastAPI 适合 Python 类型驱动的 API，与 Pydantic 结合提供请求校验及接口文档。它在这里承担网页后端职责，两阶段流程由普通 Python 模块执行。[FastAPI 官方文档](https://fastapi.tiangolo.com/)

Python 以 3.12 为目标。Node 以满足所锁定 Vite/Vue 工具链要求的版本为准，初始候选为 Node 22.18+ 的 22.x 系列；开发时验证实际环境并锁定依赖。当前 Vue 快速开始列明了 Node 版本要求，不能假定本机现有 Node 一定满足。[Vue 快速开始](https://vuejs.org/guide/quick-start.html)

## 2. 首版页面范围

| 页面 | 功能 | 不包含 |
| --- | --- | --- |
| 新建批次 | 上传 .xlsx、选择工作表、预检、查看统计、创建并开始 | 在线编辑输入和模型凭据 |
| 批次列表 | 查看批次 ID、来源文件、时间、状态和完成数量，进入详情 | 用户账号和多人权限 |
| 批次详情 | 查询进度，标签/复核/失败筛选，分页结果、记录详情、恢复/重试、导出下载 | 网页修改人工判断、回读复核结果 |

记录详情以只读方式完整展示 q、a、ref1—ref10、阶段分析、分类理由及原文引用。长资料采用可展开区块和滚动区域，不能只展示摘要后让用户无法核查。

处理进度与上传进度分别展示。处理进度来自已提交状态，显示“已处理/总数”，同时显示“已分类、失败、待复核”。上传 100% 不表示判别完成。

运行/排队时默认约每 2 秒查询状态，离开详情页后停止该页轮询；终态后停止连续查询。接口断连显示错误并有限恢复，不以本地计时虚构进度或剩余时间。

每页默认 50 条，上限 100 条，服务端分页和筛选；打开详情时再获取单条完整资料，避免每次轮询传输全部 ref。

### 3.4 配置与版本管理

.env.example 只列后端环境变量名及空值说明，例如 AIDHU_API_KEY、AIDHU_STAGE1_API_KEY、AIDHU_STAGE2_API_KEY。根目录 .env 为可选个人凭据文件，不提交；本地启动时仅后端加载，已有进程环境变量优先。具体加载工具在开发时选定并验证。

configs/config.example.toml 维护模型 ID、服务地址、超时、路径和其他非敏感参数；复制为 config.local.toml 使用。业务提示词与规则按版本维护，不能放入 .env。

前端只读取明确的公开配置；不读取后端 .env，不以 VITE_ 前缀声明模型密钥，也不把整个环境对象写入构建结果。

纳入版本管理：源码、CLAUDE.md、共享路径规则、依赖锁、无密钥模板、规划、实际文档和合成测试数据。排除：CLAUDE.local.md、settings.local.json、.env、config.local.toml、虚拟环境、node_modules、dist、data、outputs、logs。dist/frontend 可随交付包提供。原业务数据与人工核定文件单独管理。

## 4. 模块边界与调用关系

| 模块 | 负责 | 调用关系 |
| --- | --- | --- |
| frontend | 展示与用户操作 | 只访问 /api，不包含模型 SDK、凭据或判别规则 |
| api | HTTP 接收与响应 | 调用 services；不在上传请求中等待两阶段模型 |
| services | 创建、恢复、导出和快照约定 | 共用 storage/excel；网页和 CLI 复用 |
| worker | 认领任务、串行调度、汇总状态 | 调用 agent.pipeline 或导出服务 |
| agent | 两阶段输入、执行顺序与业务校验 | 调用 llm、schemas、validation |
| llm | 模型协议与统一错误 | 不决定三分类规则，不保存业务输入状态 |
| repositories | 批次、记录、阶段、任务的数据存取 | 使用 storage，供 services/worker 调用 |
| storage | 数据库连接、事务、结构与迁移 | 不依赖前端，不执行模型调用 |
| excel/evaluation | 文件及指标处理 | 不新增模型调用，不修改原预测 |

有限重试由 agent.pipeline 的阶段执行器统一管理；worker 负责调度，llm.client 单次请求，SDK 关闭额外重试。不要在客户端、worker 和 pipeline 各重试三次导致调用预算叠加。

不通过导入 rag-zero-master 业务模块复用线上问答流程，只参考服务协议与已确认配置。Milvus/ES 不成为首版运行依赖。

## 5. 本地进程架构

~~~mermaid
flowchart LR
    USER[本地浏览器] --> FRONT[Vue 静态页面]
    FRONT -->|上传 / 查询 / 恢复 / 下载| API[FastAPI：127.0.0.1:8000]
    API --> SERVICES[批次与导出服务]
    CLI[辅助命令行] --> SERVICES
    SERVICES --> DB[(本地 SQLite：队列与阶段状态)]
    WORKER[唯一串行 worker] -->|短事务认领与提交| DB
    WORKER --> PIPE[V3 资料分析 → R1 答案检查]
    PIPE --> MODELS[现有模型服务]
    API -->|按文件标识下载| FILES[输入快照与导出文件]
    WORKER -->|生成完整导出| FILES
    DB -->|进度与只读结果| API
~~~

日常运行两个进程：API 提供 /api 和前端静态构建文件；worker 消费持久化任务。开发模式额外启动 Vite，通过 /api 代理访问后端，不把模型服务暴露给浏览器。

默认约定本地 127.0.0.1:8000。前端单页路由刷新应返回 index.html，但 /api 的不存在接口仍返回 API 错误，不能被静态路由兜底吞掉。

独立 worker 是本项目的工程设计，需要实现和验证。FastAPI 的 BackgroundTasks 是响应后的后台处理机制，不提供这里需要的持久化队列、唯一消费及阶段恢复；其文档也指出较重后台任务可以采用独立工具。本项目按单机串行规模采用 SQLite 队列，首版不增加 Redis/Celery 部署。[FastAPI 后台任务文档](https://fastapi.tiangolo.com/tutorial/background-tasks/)

SQLite WAL 支持读写并行，但写入仍串行，且依赖同机文件访问。因此状态库放本地磁盘，配置有限锁等待，认领和阶段提交用短事务；远程请求、退避和导出不占有写事务。[SQLite WAL 文档](https://www.sqlite.org/wal.html)

## 6. 上传到下载的流程

1. 上传保存为服务端生成的 upload_id 文件，原文件名记录为元信息。
2. 选择工作表并预检，报告字段、编号、有效/失败/空行数。
3. 通过预检后创建 run_id，保存原始输入、配置、提示词内容和版本快照，写入队列。
4. worker 独占运行，一次认领一个任务，按输入顺序处理记录。
5. 每阶段校验后保存检查点；页面读取提交后的进度和结果。
6. 批次结束生成默认导出；用户再次导出生成新 export_id 和独立文件。
7. 按登记的文件标识下载，不接受前端提供任意磁盘路径。
8. 需要人工复核的记录保留原预测，人工在导出 Excel 中填写独立列。

上传阶段不发送模型请求。重复点击或同一 HTTP 创建请求重试使用同一幂等标识返回已有批次；有意重新上传/运行相同文件仍可以创建新批次。

创建、恢复、重新尝试失败项和导出均经统一服务校验状态。一个批次只能有一个活跃判别任务；处于 running 时不重复恢复。导出任务可能排在批次后面，页面应显示排队状态。

## 7. 拟定 API 职责

下列路径概览用于明确前后端边界。请求/响应和错误见[API 合同](08-API接口与数据合同.md)，字段与事务见[数据库设计](09-数据库与持久化设计.md)，状态及重试见[恢复设计](10-任务状态与恢复设计.md)。全部仍待审阅。

| 接口 | 职责 |
| --- | --- |
| POST /api/uploads | 接收 .xlsx，返回 upload_id 与工作表信息 |
| POST /api/uploads/{upload_id}/validate | 按指定工作表预检，返回问题位置和统计 |
| POST /api/runs | 引用已预检输入，幂等创建批次并入队 |
| GET /api/runs | 批次列表与状态 |
| GET /api/runs/{run_id} | 批次概况、进度、模型/版本、最近错误 |
| GET /api/runs/{run_id}/records | 分页/筛选摘要，不反复传输完整 ref |
| GET /api/runs/{run_id}/records/{record_key} | 完整原始输入、阶段结果与错误 |
| POST /api/runs/{run_id}/resume | 恢复/显式重试失败项，保留预算历史 |
| POST /api/runs/{run_id}/exports | 幂等创建独立导出任务 |
| GET /api/runs/{run_id}/exports | 查询历史导出与完整文件标识 |
| GET /api/jobs/{job_id} | 查询批次操作或导出任务状态 |
| GET /api/artifacts/{artifact_id}/download | 下载已生成并登记的完整文件 |

内部 record_key 用于查询，输入编号仍完整保留并作为业务关联字段；编号缺失的失败行可按来源行定位。查询路径不要求输入编号必须适合作为 URL。

敏感凭据不属于响应字段。原始资料只按文本展示，不执行其中指令、HTML 或脚本。正式业务标签只能来自校验后阶段二，不由前端根据理由推断。
