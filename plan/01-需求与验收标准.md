# 01 需求与验收标准

规划版本：v2.3｜日期：2026-10-05｜状态：待用户审阅

本文件是业务口径和验收目标的依据。工程实现见[详细设计](02-架构与详细设计.md)，指标计算见[测试与质量评估](04-测试与质量评估.md)。

## 1. 目标与评估边界

为 AIDHU 的已有回答提供三分类，帮助人工判断问题主要出在当前资料不足，还是有资料但回答错误。

输入 ref 根据问题重新从 Milvus 和 Elasticsearch 检索，并非原回答生成时实际使用的上下文。因此：

- “未检索到正确资料”表示当前提供的资料不足，不证明历史检索失败，也不证明知识库没有答案。
- “检索到正确资料但回答错误”表示当前资料可支持回答，但已有 a 不符合要求，不证明原模型当时看到了这些资料。
- 不继续区分检索算法问题与知识库缺失；不修改回答、优化检索或补充知识库。
- 判别只使用输入 q、a、ref，不访问引用链接补全文，不静默替换资料。

首版面对意图明确的问题，不实现意图检测。验收数据准备时，由人工确认记录符合该范围。

### 首版使用方式

在个人电脑本地启动程序，通过浏览器完成以下操作：

- 上传 Excel，查看字段预检结果，确认创建批次。
- 查看批次列表、处理进度、分类结果、证据与失败原因。
- 下载四表 Excel 和 JSONL 明细。
- 对中断批次发起恢复，对可重试失败发起明确的重新尝试。

刷新或关闭页面不取消已入队的批次；worker 退出时保留已提交的阶段，重新启动后由用户恢复中断批次。运行中的批次不通过重复点击创建或恢复产生重复消费。

首版页面不提供人工标注编辑，也不回读人工复核文件。人工继续在下载 Excel 的独立列填写。

## 2. 输入合同

正式输入 Excel 必须有以下 13 列：

编号、q、a、ref1、ref2、ref3、ref4、ref5、ref6、ref7、ref8、ref9、ref10。

| 内容 | 约定 |
| --- | --- |
| 编号 | 非空且唯一；原编号用于关联结果，不重新编号 |
| q | 非空，可读取的问题文本 |
| a | 非空，可读取的已有回答文本 |
| ref1—ref10 | 十列必须存在；单元格可以为空；非空值是资料文本，不仅是 URL |
| 人工标签 | 日常运行无需提供；人工核定标签仅用于独立质量评估 |
| 工作表 | 支持显式指定；优先 QA_REF；没有该表时仅在单一可见工作表情况下自动选择 |
| 额外列 | 不作为必需输入，也不发送给模型 |
| 空行 | 十三个输入字段全为空的行不构成记录；报告跳过数量 |

ref 空值表示缺少该份证据，不作为调用失败。全部为空时资料不足；若答案无法核实，按不确定规则标记复核。

缺少必要列、编号重复或无法确定工作表属于批次预检失败，在模型调用前报告。单条编号缺失、q/a 缺失或不可读取内容进入输入失败清单，其余有效记录可以处理。失败记录以来源行号追踪，不伪造业务判断。

## 3. 固定业务标签

| 标签 | 判定条件 |
| --- | --- |
| 回答正确 | 能可靠确认 a 基本正确，并回应 q 的核心需求 |
| 未检索到正确资料 | 当前 ref 不足以支持核心需求的正确回答，或必要证据适用性无法确定 |
| 检索到正确资料但回答错误 | 当前 ref 足够作答，但 a 存在关键事实错误、遗漏、误读或未完成核心回答 |

三种字符串必须完整一致。处理状态、阶段一充分性和人工复核标记不属于新增业务类别。

“回答正确”记录仍保留编号和判断；“跳过”仅表示不继续错误归因，不表示从结果文件删除。

## 4. 判别口径

资料相关不等于足够。充分性依据核心作答要点，可由多条 ref 共同支持，不要求单条资料包含全部答案。

先明确 q 需要解决什么，再看资料是否支持对应事实、条件和步骤，最后对照 a。不能因回答长、语气肯定、引用靠前或标题相关就认定正确。

| 情形 | 规则 | 是否复核 |
| --- | --- | --- |
| a 正确回应核心需求，关键结论有可靠依据 | 回答正确 | 无其他异常时不要求 |
| ref 足够，a 有关键事实错误或遗漏必要条件 | 检索到正确资料但回答错误 | 有判断不确定性时要求 |
| ref 不足，a 未完成核心回答 | 未检索到正确资料 | 根据具体不确定性决定 |
| a 看似合理，但关键结论缺少验证资料 | 暂判未检索到正确资料，不表述为已证实事实错误 | 必须 |
| ref 冲突且无法确定适用资料 | 暂判未检索到正确资料，说明冲突 | 必须 |
| 问“今年/现在”等，但缺少必要提问时间，无法确定适用资料 | 暂判未检索到正确资料；不用运行日期代替提问日期 | 必须 |
| ref 只覆盖部分核心需求，a 又误用已有部分 | 主标签为未检索到正确资料，同时记录已发现的回答错误 | 必须 |
| 阶段二对阶段一作出影响最终分类的重大更正 | 按核对后的原始证据分类，保留更正记录 | 必须 |
| 表达、排版、重复、非必要背景存在差异 | 本身不构成回答错误 | 不因此复核 |

遗漏影响结论、适用人群、必要条件、例外、金额、时间或实际操作时算关键错误。未请求且不影响核心结论的背景缺失不算错误。

“不知道”或建议咨询不自动等于正确。需要判断它是否完成 q 的核心需求；若没有完成，再根据资料充分性选择对应错误标签。

ref 出现不同日期不自动构成冲突。先检查适用对象、有效期、情境及明确版本；无法消解核心冲突时才采用暂定规则。

## 5. 人工复核交接

日常批处理只复核被标记的记录。复核清单保留 agent 暂定判断、理由、q、a 和原 ref，并设置独立的“人工判断、复核说明”列。

人工可以修订标签，但必须保留原预测，按编号关联。首版不开发复核结果导入、合并或审核页面。

“需复核”记录在工程上可以完成处理，但业务判断仍是待确认结果。运行报告分别统计处理完成和待复核数量。

上传、接口、表结构和状态设计分别见[API 合同](08-API接口与数据合同.md)、[数据库设计](09-数据库与持久化设计.md)、[恢复设计](10-任务状态与恢复设计.md)。相关初始文件大小和行数保护值属于工程方案，待审阅；超限报告问题，不部分截取输入继续判别。

## 6. 验收要求

| 编号 | 要求 | 通过条件 |
| --- | --- | --- |
| AC-01 | 输入与追踪 | 编号保留；有效、失败和未处理数量能够解释全部记录 |
| AC-02 | 两阶段执行 | 阶段一不含 a；阶段二含全部原 ref；正常记录两次调用 |
| AC-03 | 标签与证据 | 成功结果只有三种合法标签；引用能定位原文；中间结果可追踪 |
| AC-04 | 异常隔离 | 技术失败判断留空，不混入某一业务标签 |
| AC-05 | 恢复与导出 | 已保存阶段可恢复；输出不重复，不覆盖输入和已有复核文件 |
| AC-06 | 质量 | 非正确类误判为正确 ≤5%；Macro-F1 ≥0.80 |
| AC-07 | 验收完整性 | 保留验收集有效记录分类完成率 100%；无遗漏或重复 |
| AC-08 | 可使用性 | 用户能在本地浏览器上传、查看进度和结果、下载文件，并按指南恢复和填写复核列 |
| AC-09 | 页面与任务分离 | 刷新/关闭页面不停止 worker；重复提交和恢复不重复执行批次 |
| AC-10 | 多进程一致性 | API 和唯一 worker 共享同一数据库；中断恢复和查询导出不造成遗漏或状态混乱 |
| AC-11 | 预算与收尾 | 普通恢复不重置预算；未知调用占旧预算；仅收尾恢复不调用模型 |
| AC-12 | 文件发布 | 导出失败不改变分类结果；Excel/JSONL 完整发布后才提供下载 |

5% 的分母是人工核定为两种非正确标签的记录数，分子是其中被 agent 判为“回答正确”的数量。这是三分类混淆指标，不能把所有资料不足样本称为已证实的事实错误。

各类指标、复核比例、技术失败及样本数一并报告；不设置尚无依据的耗时或复核比例硬门槛。质量目标尚未实测，不是准确率承诺。
