# 05 交付与运行指南

规划版本：v2.3｜日期：2026-10-05｜状态：待用户审阅

本文件规定未来首版的交付和使用方式。目录、脚本、命令是拟定接口，尚不能在当前项目中直接运行；开发交付时必须用实际程序验证并更新示例。

## 2. 环境与配置

项目根目录为 D:/pyProjects/dha_projects/aidhu_om_agent。根目录 pyproject.toml/uv.lock 管理 Python，package.json/pnpm-lock.yaml 管理前端；后端采用独立虚拟环境，前端使用 pnpm。精确版本在开发验证后记录，不复制旧项目虚拟环境。

| 路径 | 职责 |
| --- | --- |
| configs/config.example.toml | 无密钥模板，复制为 configs/config.local.toml |
| data/uploads/ | 后端生成唯一文件名的输入快照；原文件名只作元信息 |
| data/state.sqlite3 | API 与 worker 共享的批次、阶段、队列及尝试记录 |
| outputs/<run_id>/ | 独立导出的 Excel、JSONL 和评估报告 |
| logs/ | API/worker 脱敏运行日志 |
| dist/frontend/ | 根目录统一构建的前端文件，由 FastAPI 提供静态访问 |
| .env.example / .env | 后端变量模板/可选个人凭据文件；模板无真实密钥，个人文件不提交 |

所有运行路径统一相对项目根目录解析，不受脚本当前工作目录影响。

凭据使用 AIDHU_API_KEY。两阶段独立变量为 AIDHU_STAGE1_API_KEY、AIDHU_STAGE2_API_KEY；未设置时回退到默认变量。环境变量只在后端进程运行时读取，不保存实际值，也不传给前端。使用可选根目录 .env 时仅后端加载，已有进程环境变量优先；模板 .env.example 不含真实值。

初始配置默认阶段一 deepseek-v3/120 秒，阶段二 deepseek-r1/300 秒，串行，每阶段最多 3 次尝试。服务地址按实际现有服务填写。页面首版不编辑模型服务和凭据；需要修改配置时按指南在本地完成。

实际服务若不支持某参数，先验证并修正配置。输出上限、上下文容量及依赖版本在 M2/M6 记录。

## 3. 启动方式

首版使用一个 API 进程和一个 worker 进程。前端构建后由 API 同端口提供，默认本地地址 http://127.0.0.1:8000。服务默认只监听本机。

以下是计划中的命令，需等待开发交付后使用：

~~~powershell
.\scripts\start-local.ps1
.\scripts\stop-local.ps1
~~~

启动脚本验证配置、静态文件和数据库版本，避免重复启动。后台进程使用隐藏窗口，PID 和运行标识保存在本地运行目录；停止脚本核验归属后只停止本项目进程，不按进程名结束其他 Python 服务。

停止时尽量完成当前阶段提交；强制中断仍按断点恢复约定处理。关闭浏览器不会调用停止脚本，也不会结束正在运行的批次。

开发时单独运行 Vite，默认 http://127.0.0.1:5173，通过代理访问 /api。API、worker 和 Vite 合计三个进程。日常使用不需要运行 Vite 开发服务器；交付包含已构建的前端文件。

构建命令约定为：在项目根目录执行 pnpm install --frozen-lockfile、pnpm run typecheck、pnpm run build，输出到 dist/frontend；后端从根目录 pyproject.toml/uv.lock 安装锁定依赖。pnpm 的冻结锁安装在依赖清单与锁文件不一致时拒绝更新，适合交付复验。[pnpm 安装文档](https://pnpm.io/cli/install)

这些命令要求开发阶段已经生成并锁定对应文件，当前不可直接用于本项目。Windows 干净环境复验时记录完整安装命令。

## 4. 浏览器使用流程

1. 打开本地地址，在“新建批次”页上传 Excel。
2. 选择工作表并预检。优先 QA_REF；不确定时由用户选择。缺列或重复编号先修正，未通过前不能创建批次。
3. 查看有效/输入失败/跳过空行数，点击“创建并开始”。返回批次 ID，任务入队。
4. 在批次详情查看排队/运行状态、处理进度和成功/失败/待复核数量。页面显示已提交结果。
5. 查看标签、理由和原文证据；需要时打开 q/a/全部 ref 的只读详情。
6. 判别结束后默认导出任务入队，文件生成完毕才能下载 Excel 和 JSONL；重新导出产生新文件。运行中也可请求导出，快照按实际执行时的已提交数据捕获，可能等待当前批次结束。
7. 程序中断后重新启动，在批次列表找到 interrupted 批次并选择恢复；预算耗尽的失败项需要显式重新尝试。
8. 下载复核清单，在“人工判断、复核说明”列填写并另存。

进度包括已分类和已确认失败行；处理 100% 与分类成功 100% 分别显示。需复核不是技术失败，不显示为第四种标签。

刷新页面或关闭浏览器后任务继续；重新打开列表可找到批次。worker 退出后保留提交结果，不自动继续遗留 running 任务。全部记录已保存但未收尾时，恢复仅补状态和默认导出，不新增模型调用。普通恢复不加次数；页面明确显示显式重试预计重开的数量。

## 5. 辅助命令行接口

网页是日常入口，CLI 用于调试、恢复、导出及验收评估。拟定统一入口为 python -m aidhu_om_agent，包安装后提供：

| 命令 | 用途 | 必要参数 |
| --- | --- | --- |
| run | 预检输入、保存快照并入队新批次；不直接执行模型 | --input、--config；可选 --sheet、--wait |
| resume | 将原批次未完成记录入队，拒绝重复活跃任务 | --run-id；可选 --retry-failed、--wait |
| export | 从保存状态入队独立导出任务 | --run-id；可选 --wait |
| evaluate | 对照人工核定标签，使用原预测计算指标 | --run-id、--gold、--split-manifest、--split |

~~~text
python -m aidhu_om_agent run --input "D:/data/qa.xlsx" --config "configs/config.local.toml" --sheet QA_REF --wait
python -m aidhu_om_agent resume --run-id "<批次ID>" --wait
python -m aidhu_om_agent resume --run-id "<批次ID>" --retry-failed --wait
python -m aidhu_om_agent export --run-id "<批次ID>" --wait
python -m aidhu_om_agent evaluate --run-id "<批次ID>" --gold "D:/data/gold.xlsx" --split-manifest "D:/data/split.json" --split holdout
~~~

run/resume/export 共用持久化队列，要求唯一 worker 已启动。--wait 仅等待并报告任务结果，不启动第二个消费进程；不带 --wait 时返回标识及入队状态，不能把入队成功等同分类成功。evaluate 读取保存状态，不调用模型，不依赖 worker 执行。

run 创建新批次，不静默复用其他批次结果。resume 使用原输入、提示词和非敏感配置快照，验证版本兼容；输入、模型或规则改变时重新 run。

等待模式下，正常完成且无技术失败返回成功；部分失败或系统故障返回非成功状态。导出单独报告文件生成状态；复核标记本身不改变成功状态。

## 6. 输入与结果阅读

运行前保证编号唯一、q/a 非空、十个 ref 列存在。意图明确由业务提供方保证；不需要人工标签。

| 工作表 | 阅读方式 |
| --- | --- |
| 分类结果 | 编号、原预测、理由、证据、复核标记和处理状态 |
| 复核清单 | 被标记记录的 q/a/原始 ref 与独立人工填写列 |
| 失败清单 | 失败阶段、原因、来源行和尝试次数 |
| 运行概况 | 已分类、失败、未处理、复核数量，模型与版本 |

JSONL 保存两阶段明细；成功但需复核保留暂定标签，失败和未处理判断留空。人工复核文件不回读，原预测不被覆盖。

## 7. 恢复与人工处理

| 情况 | 用户操作 |
| --- | --- |
| worker 退出/程序中断 | 重新启动；按批次 ID 恢复 interrupted 任务 |
| 临时失败且预算未耗尽 | 恢复后用剩余次数处理 |
| 预算耗尽 | 对可沿用原输入/配置的失败项明确重新尝试或 --retry-failed，新增预算轮次并保留历史 |
| 全部分类已保存、仅批次未结束 | 使用恢复补齐终态和导出，程序不再次调用模型 |
| 认证错误 | 修正环境凭据；模型/服务配置改变时新建批次 |
| 输入或资料需修改 | 修正 Excel 后新建批次 |
| 原批次规则/结构不兼容 | 使用对应程序版本恢复，或按新版本重新创建 |
| 输入超限/输出截断 | 检查服务容量和配置，不在后台裁减 ref |
| 导出失败 | 保留已分类数据，修正文件写入问题后重新导出 |
| 需人工复核 | 在独立人工列填写并另存，不覆盖预测 |

详细接口和恢复语义见[API 合同](08-API接口与数据合同.md)、[任务状态与恢复](10-任务状态与恢复设计.md)。页面 HTTP 接受成功仅表示操作已保存/入队，模型分类与文件生成分别查询。

## 8. 交付复验

Windows 干净环境按锁定依赖完成安装、前端类型检查和构建，验证启动/停止及四个命令帮助。

使用独立示例完成网页上传、预检、创建、查看证据、下载；刷新/关闭浏览器后验证 worker 继续执行。另验证 API 重启、多进程独占、阶段一提交后的中断恢复、部分失败及重复导出。

核对四表、JSONL、编号和统计一致，API 响应和前端构建文件无模型密钥。工程、网页和真实分类验收分别记录，不宣称未经验证的准确率或耗时。
