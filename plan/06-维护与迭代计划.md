# 06 维护与迭代计划

规划版本：v2.3｜日期：2026-10-05｜状态：待用户审阅

维护以实际误判和使用反馈为依据。首版尚未开发，本文件规定交付后的记录和变更流程，不创建定时任务或监控服务。

## 1. 误判记录

人工复核结果与 agent 原预测分别保留。误判清单至少记录：

| 内容 | 用途 |
| --- | --- |
| 编号、run_id、输入摘要 | 找到对应原记录 |
| agent 判断、人工判断 | 观察类别混淆 |
| 人工理由与关键 ref | 可核查的更正依据 |
| 原阶段一/二结果 | 定位错误发生阶段 |
| 规则、提示词、结构及模型配置版本 | 比较变更效果 |
| 修复项和复验结果 | 判断问题是否解决 |

误判分析采用以下工程归因，它们不写入业务“判断”列：

- 阶段一遗漏证据或误读适用条件。
- 阶段二未核对原文、误用阶段一摘要或错误检查 a。
- 业务边界不清，如关键遗漏、时间或混合错误的口径不一致。
- 结构、引用、运行状态或导出问题。
- 当前输入缺少足以确定结论的信息。

需要再细分检索算法和知识库缺失时另立需求，不根据本次重新检索资料推断历史线上故障。

## 2. 版本管理

| 对象 | 变更要求 |
| --- | --- |
| 需求/标签规则 | 更新需求文档和规则版本，说明行为变化 |
| 两阶段提示词 | 分别维护版本和内容摘要 |
| 输出结构/校验 | 更新结构版本、详细设计及兼容说明 |
| 模型/服务配置 | 记录实际模型标识、服务和参数；服务版本未提供时注明未知 |
| 人工标准 | 新增标签版本，保存核定记录及变更理由 |
| 验收数据与划分 | 保存摘要、清单及用途，不能把已调试集合重新称为独立保留集 |
| 程序与文档 | 维护发布记录和对应测试报告 |
| API / 前端 | 响应字段和状态语义保持一致，前后端版本配套交付 |
| 数据库与 worker | 迁移前备份；回归队列认领、重试、恢复和多进程读写 |

恢复只能使用原批次一致的版本。规则或配置变化后新建批次；旧结果保留并注明原版本，不覆盖成新预测。

## 3. 变更流程

1. 根据人工证据记录问题，不仅凭模型自评提出修复结论。
2. 判断属于业务口径、提示词、模型配置还是工程实现。
3. 更新相关规划和版本，补充可验证案例。
4. 在校准/回归数据上验证，检查新增类别混淆和复核数量。
5. 若变更影响分类行为，以未用于调试的数据进行质量验收。
6. 发布新版本并保留变更前后的报告；需要时使用旧版本和快照回退。

修复输出字段或存储错误时，额外核对导出和恢复。修改阶段一时，检查阶段二是否受到证据变化影响；修改阶段二时，检查正确标签误报是否增加。

## 4. 运行与数据管理

每批次人工查看运行概况：成功、失败、未处理、复核、调用量、耗时和可用用量。持续出现认证、参数或超限问题时，先修正兼容配置再继续。

数据库、上传快照、JSONL 和人工核定文件由用户管理备份；恢复验证以实际可读的快照为依据。SQLite 启用 WAL 时，采用数据库备份接口或停止 API/worker 后按一致性方案备份，不在运行中只复制主数据库文件。日志仅保留必要的脱敏错误，不保存密钥。

本地升级前确认批次已结束或中断，保存原配置与版本。重启后检查队列、已提交阶段和静态前端版本；浏览器关闭不会停止 worker，退出程序通过项目停止入口管理所属进程。

首版不设置未经用户确认的自动清理期限。清理运行文件前确认复核、审计和评估资料已另存；删除旧结果不能改变已报告的样本分母。

模型标识相同不保证服务内部版本永远相同。能够取得实际版本时记录，无法取得时明确缺失，不宣称远程结果可完全复现。

维护中不手动清空 call_attempts 或覆盖 stage_results 来让任务看似成功。修订规则/输入后创建新批次；重开预算按状态设计新增 campaign；导出重新生成使用新 export_id。字段变化同步更新[API](08-API接口与数据合同.md)和[数据库](09-数据库与持久化设计.md)，执行[恢复回归](10-任务状态与恢复设计.md)。

## 5. 后续扩展触发条件

| 扩展 | 触发条件与前置工作 |
| --- | --- |
| 人工复核回读 | 用户需要程序生成最终汇总；先明确字段、覆盖与审计规则 |
| 更高并发/更大批量 | 实测串行耗时不能满足需求；先确认服务限流与存储一致性 |
| 多人共享或线上部署 | 当前已有本地 API 和只读管理页面；共享时另行规划身份、权限、存储和部署 |
| 网页人工复核 | 用户需要直接在页面修改标签时，明确原预测保留、审计及导出规则 |
| 多模型复核 | 已定位单次判断的不稳定性；先估算用量并设计独立验证 |
| 原始检索归因 | 保存原回答当时的上下文、检索版本和时间后再规划 |
| 检索算法/知识库细分 | 用户启动下一阶段，准备对应知识库核查依据 |

上述内容不计入首版开发任务。增加能力后更新需求、架构、测试和交付文档，重新定义受影响的验收条件。

## 6. 发布状态

首版只有在工程验证、正式分类验收和用户业务验收完成后才能标记为已交付。

本轮发布的是 v2.3 规划文档，按用户标准调整开发辅助规则、源码、测试、文档和依赖目录；业务范围及既有 API/状态方案不变，状态为待审阅。进一步细节留到开发时完善；程序发布、模型兼容验证和准确率验收尚未进行。
