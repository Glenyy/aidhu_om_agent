## 5. 遗留问题

**S02 范围内无业务遗留。** 以下为已知工程口径，转入后续阶段处理，不影响本阶段完成条件：

- 用户真实文件里「除编号外全空」的 90 行被计为**输入失败**（而非「跳过空行」），这是 S02 合同的既定语义：只要有任意单元格非空却缺 q 或 a，就报输入错误、不静默丢弃。若用户希望这类行被当作空行，需要在源文件里清空编号列或删行。
- 编号列为数值型时**不补前导零**（`NUMERIC_RECORD_ID_LEADING_ZEROS` 已提示）；编号仍按原值关联。
- 前端产物单包体积偏大（Element Plus 全量引入，见 [S03 自动化审阅](../../automated/S03/r01-自动化审阅.md) §4 第 8 条）——S06 页面实现时评估。
- 未清除的公开残留：首次提交曾误含 `memory/` 记忆文件，旧提交对象仍可按 SHA 公开访问；是否联系 GitHub Support 彻底清除**用户尚未决定**（详见 [HANDOFF](../../../../HANDOFF.md)）。
