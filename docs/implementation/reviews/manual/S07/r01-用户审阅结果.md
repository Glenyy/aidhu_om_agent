### 2.3 用户遇到过的一次失败：不是程序缺陷

用户在执行 A6 时贴出 `系统找不到指定的文件。` 的截图。**根因不在程序，而在指南的占位符写法**：指南写 `--run-id <run_id>`，用户在 Anaconda Prompt（cmd）里**连尖括号一起粘贴**，而 cmd 把 `<`／`>` 当重定向符，于是该行被解析成「从名为 `3004c1c3…` 的文件读入标准输入」——文件不存在即报此错，**`python` 根本未被启动**（所以没有任何程序输出）。去掉尖括号后命令正常。

已核实的旁证：该用户的 `evaluate` **确实是在之后跑成功的**——`evaluations` 行创建于 12:11:55Z，各项数值与指南 A6 的「应观察」**逐字一致**（§2.1）。

### 2.4 验收后只读核对发现的指南笔误（B9）

只读核对时发现指南 **B9「冻结版本清单」** 的「应观察」里有一处**写错的数**：原文写「不含任何凭据（`api_key_present` 为 `false`）」。**实测该值在本机为 `true`**——

- 代码：`services/batches.py` 的 `model_config_snapshot()` 只取白名单键，`api_key_present` 由 `config.py` 生成，语义是「**是否配置了 Key**」（`bool(stage.api_key)`），**不是密钥值本身**；
- 本机证据：用户库中该评估的 `versions_json.model_config` 为 `{"stage1": {"api_key_present": true, …}, "stage2": {"api_key_present": true, …}}`；同一结论亦见于 [S03 自动化审阅](../../automated/S03/r01-自动化审阅.md) §2 命令 7（「两阶段 `api_key_present: true`」）。用**不带密钥的模板配置**跑时才是 `false`（[S01 自动化审阅](../../automated/S01/r01-自动化审阅.md) 命令 14）。

**性质判定**：这是**指南文本的错误，不是程序缺陷**——页面如实渲染该布尔值（`EvaluationView.vue` 直接输出 `model_config` 的 JSON），「不含任何凭据」这一句仍然成立（快照里没有任何密钥内容）。指南该处**已就地更正**，并在文末附「事后记录（开发者补记）」说明原文写的是什么。**用户未报告此项**，本记录不声称用户的 B9 核对与更正后的文本一致。
