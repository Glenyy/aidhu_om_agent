## 1. 准备与启动

### 1.1 启动界面服务（窗口 A）

打开 Anaconda Prompt：

```bat
conda activate aidhu_agent
cd /d D:\pyProjects\dha_projects\aidhu_om_agent
python -m aidhu_om_agent serve
```

应观察：

```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
界面地址：http://127.0.0.1:8000/（按 Ctrl+C 停止）
```

**保持窗口 A 开着**。若 8000 被占用，改用 `python -m aidhu_om_agent serve --port 8124`，后文端口随之替换。

> **⚠ 第一次运行会升级你自己的数据库结构，并先自动备份**：本机 `data/state.sqlite3` 在 2026-10-07 检查时仍是**结构版本 2**（`schema_migrations` 里只有 1、2 两行，共 8 个既有批次），而 S07 把结构升到**版本 3**（新增 `evaluations` 与 `evaluation_records` 两张表）。升级**在启动时自动完成**，且**升级前**会把旧库整份备份到数据库同级的 `data/backups/state-v2-<时间戳>.sqlite3`。
> 请核对：启动后 `data/backups/` 目录**出现了**、里面有一个 `state-v2-*.sqlite3`。**不要删它**（备份文件按约定不自动清理）。既有 8 个批次的数据不会被改动。
> 若你的机器上这个库**已经是**版本 3（例如你之前已经跑过 S07 的代码），那 `data/backups/` 可能已有更早的一份备份、这次不再新增——这也是正常的，见 §3 第 3 项。

`python -V` 若不是 `Python 3.12.15`，把上面的 `python` 换成 `D:\anaconda\envs\aidhu_agent\python.exe`。

### 1.2 启动队列消费者（窗口 B）

**再开一个** Anaconda Prompt：

```bat
conda activate aidhu_agent
cd /d D:\pyProjects\dha_projects\aidhu_om_agent
python -m aidhu_om_agent worker --mode mock
```

应观察：

```
worker w-………… 已启动（模式 mock）；数据库 …\data\state.sqlite3
```

**`--mode mock` 是本指南的硬要求**：整批用模拟模式跑，**零真实调用、零费用**。**不要**用 `--mode real`（那会真的调用模型服务并产生费用，且需要另行授权）。**保持窗口 B 开着**；整批入队后由它认领执行。

### 1.3 准备数据（`data/evaluation/demo/`）

本指南只用**一个**上传文件：

| 文件 | 用途 | 关键内容 |
| --- | --- | --- |
| `data/evaluation/demo/calibration-v1.xlsx` | **你要上传的批次输入** | 工作表 `QA_REF`，20 条记录（含 1 条会技术失败的 `FF-1`） |
| `data/evaluation/demo/gold-v1.xlsx` | `evaluate` 的**人工核定文件** | 工作表 `QA_REF`（37 行）+ `核定元数据`（4 项）；由它生成划分清单 |
| `data/evaluation/demo/split-v1.json` | **划分清单** | seed `20261005`；校准 20／保留 17；强制进校准集 `["1","4"]` |

**这三个文件是怎么来的（如实说明，别当它是产品功能产出）**：它们是**本机合成数据**，由本机脚本 `data/runtime/s07_demo_prepare.py` 生成（**`data/**` 已 gitignore，不入版本库**）。划分清单**由产品里真实的 `plan_split` 函数算出**，两个子集工作簿由它交付的编号从核定文件导出。万一这三个文件在你机器上不在了，可以在项目根用 `python data/runtime/s07_demo_prepare.py` 重新生成（**它同时也是那个「没有面向用户入口」的临时手段**）；本指南的数值对应的是**当前这组文件**，重新生成后请以 `data/evaluation/demo/expected.json` 里的数字为准。

**这里有一处需要你决定的产品缺口**（自动化审阅 §4 第 3 行已记）：**S07-02 批准的「固定分层划分与子集生成」目前只有 Python 函数 `generate_split`，没有面向用户的命令或按钮**——你自己**无法用产品命令**产出 `split-v1.json` 与两个子集工作簿。开发者为完成本指南的演示链路写了上面那个本机脚本，**没有擅自加新子命令**（新增接口＝扩大批准范围）。**这一项同时挡住 S07-04**（真实校准必须先有划分产物）。

`holdout-v1.xlsx` 也在同一目录（保留集子集）——**本指南不使用它，请勿上传**：保留集在本阶段一次都不跑。

### 1.4 打开页面并强制刷新

浏览器打开 **http://127.0.0.1:8000/** ，按 **`Ctrl+F5`**（强制刷新，避免拿到旧的构建产物）。顶部是标题「AIDHU 回答判别 Agent」与导航「判一条 ／ 批次」。

### 1.5 关于费用、凭据与数据位置

- **费用**：窗口 B 以 `--mode mock` 运行，**不调用任何模型服务，费用为 0**；`evaluate` **完全不调用模型**（它读的是批次里已经存在的原预测）。
- **凭据**：本指南不需要任何 API Key；配置文件不会被修改，也不新增配置键。
- **数据位置**：新批次进 `data/state.sqlite3`，上传的 xlsx 进 `data/uploads/`，评估报告进 `data/evaluation/reports/`（页面只显示文件名，不显示本机路径）。

> 本指南**不新建**批次以外的任何东西；A 组会建 **1 个批次**（模拟跑，零费用）与 **1 份评估记录**。重复操作会各自多出一份，属正常。

## 5. 结束、恢复与文件保存

- **停止**：两个窗口各按 `Ctrl+C`。服务停止不影响已落库的批次与评估；worker 停止时未消费的任务保持 `queued`，重启后会继续。
- **恢复**：把窗口 A／B 重新起起来即可；批次详情页与评估页的「立即刷新」会读到最新状态。**只看评估结果**时，无需启动窗口 B（评估不依赖 worker）。
- **重跑**：A1—A6 可以整体重跑，会**新建一个批次与一份评估**（模拟跑，零费用），数字应当**逐位相同**（划分固定种子、预测是模拟模式确定性映射）；`run_id`／`evaluation_id`／报告文件名会变。同一批次也可以**再评一次**（例如换个划分），评估历史会累积成多份。
- **需要保留的文件**：`data/state.sqlite3`（批次／记录／评估）、`data/uploads/`（原始 xlsx）、**`data/backups/state-v2-*.sqlite3`（迁移前备份，请勿删除）**、`data/evaluation/reports/`（评估报告）。
- **不改动**你的 `configs/config.local.toml`：本阶段不新增任何配置键。

4. **占位符写法提醒**：A6 与 §3.1 中的 `<run_id>` 是**占位符**，粘贴到 Windows 的 cmd（Anaconda Prompt）时**必须把尖括号本身删掉**——cmd 会把 `<`／`>` 当重定向符，导致 `系统找不到指定的文件。` 且命令根本不执行（用户本轮实际遇到过一次，见用户结果文件 §2.3）。本条是**说明性补记**，原文未改，以免改动你已核对过的文本。
