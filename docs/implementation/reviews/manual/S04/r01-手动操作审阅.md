## 1. 准备与启动

### 1.1 启动界面服务（窗口 A）

打开 Anaconda Prompt：

```bat
conda activate aidhu_agent
cd /d D:\pyProjects\dha_projects\aidhu_om_agent
python -m aidhu_om_agent serve
```

应观察：

```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
界面地址：http://127.0.0.1:8000/（按 Ctrl+C 停止）
```

**保持窗口 A 开着**。若 8000 被占用，改用 `python -m aidhu_om_agent serve --port 8124`，后文端口随之替换。

`python -V` 若不是 `Python 3.12.15`，把上面的 `python` 换成 `D:\anaconda\envs\aidhu_agent\python.exe`。

### 1.2 启动队列消费者（窗口 B）——本轮新增

**再开一个** Anaconda Prompt，做同样的三步，但命令换成 worker：

```bat
conda activate aidhu_agent
cd /d D:\pyProjects\dha_projects\aidhu_om_agent
python -m aidhu_om_agent worker
```

应观察：

```
worker w-<12 位标识> 已启动（模式 mock）；数据库 <项目根>\data\state.sqlite3
按 Ctrl+C 停止；退出时保留未消费的 queued 任务。
```

之后它是**安静**的——空队列时不会刷屏，只在真的消费到任务时才有输出。不要以为它死了；窗口 B 停住不动是正常的。

- **默认就是模拟模式**（`--mode mock`），不调用真实模型、零费用。**不要**加 `--mode real`。
- **窗口 B 必须一直开着**：你在界面上点「开始判别（整批）」只是把任务**入队**，真正执行靠它。
- 同一时刻**只允许一个 worker**。再开一个会立刻退出（见 §5.1），这是设计如此。
- 想让它跑一会儿就退出，可以改成 `python -m aidhu_om_agent worker --once`（消费完当前队列就退出）。

### 1.3 打开页面并强制刷新

浏览器访问 **http://127.0.0.1:8000/** ，按一次 **`Ctrl+F5`**。

**本轮前端有改动，必须强刷**，否则你会看到旧页面、以为没变化。判定方法：按 `F12` → Network，页面加载的脚本名应为 **`assets/index-zZESsEwi.js`**（上一轮是 `index-BCkl9iws.js`）；样式为 `assets/index-CnX9Ulg1.css`。

`dist/frontend` 已是本次重建的产物；若页面 404，在**另一个**终端执行 `pnpm install` 后 `pnpm build`。静态文件按请求读盘，重建后**不需要重启服务**。

### 1.4 关于费用、凭据与数据位置

- **本指南全部步骤走模拟模式，不调用任何真实模型、零费用。** 本轮真实调用预算为 **0**（S03-06 的 10/10 已用满），因此指南**不含**任何真实模式步骤。
- 模拟结果由程序内确定性合成逻辑生成，界面上带橙色标识（批次详情「调用统计」右侧的「含模拟调用（N / M 次），不是真实模型结果」），**不能作为模型分类质量的证据**。同一份样例的同一编号，每次判都一样。
- 你不需要输入任何密钥。凭据只以「是否存在」（`api_key_present`）出现在批次详情里，**不写进页面、日志或数据库快照**。
- **本轮开始会落盘**（这是本阶段的重点）：
  - 数据库：`data\state.sqlite3`（首次启动服务时自动创建）
  - 上传的原始文件：`data\uploads\`
  - 迁移前自动备份：`data\backups\`
  - **不会**产生任何导出文件（导出属 S05/S06，界面不提供下载；`latest_export` 恒为空，不登记假产物）。

## 2. 审阅步骤

A 组是核心成功流程与失败族，B 组是中断与恢复，C 组是持久化（本阶段重点）。**三组都要做**；C 组需要 A、B 已经留下数据。

> **核对数字的通用规则**：同一批次的计数满足 `total = valid + input_invalid` 与 `processed = classified + failed + input_invalid`。**已结束的批次不一定 100%**——失败与输入失败记录不计为成功，详情页进度条下方有这句说明。
