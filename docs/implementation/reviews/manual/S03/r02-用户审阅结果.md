## 5. 遗留问题（转入 S04 或后续处理，不作为 S03 完成条件）

### 5.1 真实文件记录 `4` 的失败族（用户 2026-10-06 决定转 S04／后续）

诊断产物 `data/runtime/judge-diagnostics/judge-58fdbfbf85c447ad810f0e62de66ad7a.json` 记录的**三种不同机制**（字符级事实，来自诊断文件本身）：

1. **摘录跨行拼接**：模型跳过表格中的一行后把前后内容接起来，摘录**不是连续原文**（首处分歧落在该行拼接处，最长公共子串长度 179 / 摘录长 279）。
2. **改写字符**：把 markdown 列表符 `-` 写成 `•`；另一处把某列表项的行首列表符吃掉（LCS 仅 9 字符）。
3. **输出不是合法 JSON**：`Invalid control character at（位置 503）`——模型在 JSON 字符串内写了**真实换行**（位置 503 正是逐字复制表格处），**不是子串问题**。此机制暴露一处结构性张力：提示词要求「原样保留换行」，而 JSON 字符串内换行必须写成 `\n`；R-2 对 `format` 类错误给的是通用提示，**未点明这一条**。

**建议方向**（须在 S04 或后续阶段按阶段执行规则讨论定稿并获批准，**未经批准不得动代码**）：提示词显式区分「内容逐字」与「JSON 换行须转义」；明确禁止改写列表符、禁止跨行拼接；或按 [r02 自动化审阅 §0.4](../../automated/S03/r02-自动化审阅.md) 既有分支考虑解析期输入规范化 / 放宽匹配口径（两者均属改契约）。
