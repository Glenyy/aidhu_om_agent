## 3. 代码与合同核对

### 3.1 存储与迁移（S04-01）

- `storage/migrations/001_init.sql` 建全部表，`002_worker_visibility.sql` 补 worker 可见性字段；`schema_migrations(version, script_sha256, applied_at)` 记录结构版本，当前 `schema = 2`（§2 命令 9 的 `versions.schema`）。
- 每操作独立连接；连接上显式执行并**回读验证** `PRAGMA foreign_keys=ON`、启用 WAL、设置有限 `busy_timeout`；写事务显式 `BEGIN IMMEDIATE`（`isolation_level=None`）。
- **本轮新增** `read_transaction()`（[storage/database.py](../../../../../src/aidhu_om_agent/storage/database.py)）：读接口用延迟 `BEGIN` 而不是 `BEGIN IMMEDIATE`——读请求不该抢写锁、也不该被写事务挡在门外；结束一律 `ROLLBACK` 释放快照。**动机是 [plan/08 §5](../../../../../plan/08-API接口与数据合同.md) 明确要求「上述计数与状态在同一读取快照中获得」**：没有它，WAL 连接会为每条 SELECT 取新快照，界面上可能出现「失败 1 条，但失败列表是空的」。嵌套调用会抛 `DatabaseError`，不静默降级。
- 未引入任何新依赖（无 Alembic）；迁移在 worker 消费前串行执行，迁移前备份到 `data/backups/`。

### 3.2 上传/预检/批次/记录持久化（S04-02）

- `uploads`/`input_validations` 落库（替换 S03 的内存表），`runs` 带 `upload_id`/`validation_id` 外键；HTTP 接口形状**未变**——这正是 §2 命令 8 中「重启后同一个 `validation_id` 仍可创建批次、同一 `run_id` 仍可查询」得以成立的原因。
- 创建批次时冻结三份快照：`config_snapshot_json`（凭据只以 `api_key_present` 形式）、`versions_json`、`prompt_snapshot_json`（两份提示词**全文** + sha256）。同事务写幂等键。
- 计数恒等式 `total = valid + input_invalid` 与 `processed = classified + failed + input_invalid` 由 §2 命令 8 的实测值核对：`3 = 3 + 0`、`3 = 2 + 1 + 0`。

### 3.3 持久化阶段预算与提交（S04-03）

- 调用前在短事务内占位 `call_attempts`；成功后在**同一事务**写 `stage_results` + 记录状态/投影 + `runs.revision`。因此「尝试记为成功、阶段结果却没有」的半次提交不可能出现（`test_interruptions.py` 的事务回滚用例覆盖）。
- 阶段二失败时阶段一结果**保留**（[plan/10 §3](../../../../../plan/10-任务状态与恢复设计.md)）：§2 命令 8 中 `stage1.attempts = 3` 全部成功，失败只发生在阶段二。
- `current_attempt` 改从账本读，不再依赖 S03 的 `_ReportingClient` 计数（该计数只在账本从空开始时成立，S03 已披露）。

### 3.4 唯一 worker 与队列认领（S04-04）

- OS 级文件独占锁（Windows `msvcrt.locking`／POSIX `fcntl.flock`）+ 数据库执行槽双检查；**不是 PID 文件**（进程被杀后操作系统自动释放锁，残留 PID 文件会把「还活着吗」变成猜谜）。
- 锁被占用时抛 `WorkerLockError`，**在此之前不碰数据库**，退出码 3，队列状态不变。
- 队列按 `created_at, job_id` 串行认领，认领即占执行槽并把批次改为 `running`；判别派发暂停时任务**保留在队列**、不消费也不标失败。
- §2 命令 8 真实执行的 `worker --once`（默认 `mock` 模式）消费 1 个任务后退出，退出码 0。

### 3.5 普通恢复与显式重试（S04-05）

- `POST /api/runs/{run_id}/resume` 只**入队**，返回 `selected_records`／`renewed_campaigns`／`skipped_budget_exhausted`／`finalize_only`／`dispatch_paused`；真正执行由 worker 认领时落实。
- 恢复**沿用批次快照的提示词与 schema 版本**，不用磁盘当前版本；语义不可执行时返回 `VERSION_INCOMPATIBLE`。
- §2 命令 8 中该批次的表现正好展示了「重试 ≠ 必成功」与「预算用尽」两条：`can_resume=false` + `skipped_budget_exhausted=1`（阶段二 3 次预算已用满），而 `can_retry_failed=true`（显式重试会**重开预算**）。
- 界面按钮的可用性直接来自后端 `allowed_actions`，与提交路径同源，**不会出现「按钮可点却被拒」**（`test_api_s04_reads.py` 对两者一起断言）。

### 3.6 中断与多进程验证（S04-06）

- 五个中断点（占位前／占位后／阶段一提交后／阶段二提交后／收尾前）+ 事务回滚 + 双 worker 拒绝，全部用 `FaultyDatabase` 在连接层注入 `KillSwitch`（继承 `BaseException`，worker 的 `except` 不会误吞）验证。
- `running` 的调用在**新 worker 取得独占锁后的启动恢复**中改为 `unknown_after_interrupt`，**继续占用旧预算**（预算不退还）；`running` 任务改 `interrupted`，批次改 `interrupted`。
- 本条与阶段文档 §0.4 ③ 的界面措辞绑定：详情页只报「最近一次登记的 worker 与上线时间」，**不据时间戳断言进程已死**（§2 命令 5 已核对文案进入产物）。

### 3.7 最小批次界面与接口（S04-07）

- 新增 `GET /api/runs`（分页 `items/page/page_size/total`，默认 50、上限 100，排序 `created_at DESC, run_id DESC`）与 `GET /api/runs/{run_id}`（[plan/08 §5](../../../../../plan/08-API接口与数据合同.md) 的全部字段）。
- 详情页新增两项**超出 §5 最小集合**但为界面必需的内容：`recent_jobs`（`active_job` 恰好在批次结束时为 `null`，而用户最想看的就是最后那个任务的终态与错误）与 `execution_control.last_worker`。两者都是**只读的既有数据**，不改判定与状态机。
- 前端：`/` 单页在预检通过后新增「开始判别（整批）」（生成幂等键 → 创建批次 → 跳转详情）；新增 `/runs` 列表与 `/runs/{run_id}` 详情，轮询约 2 秒、进入终态停止；`interrupted` **不算**终态（要等新 worker 或用户点恢复）；只要存在 `active_job` 就继续轮询。
- **history 深链接**：`StaticFiles(html=True)` 只对目录回落，刷新 `/runs/{id}` 会得到 404 JSON——与「重启服务后刷新仍在」直接冲突。改为 `_mount_frontend` 显式回落（见 §4 问题 1）。
- 模拟模式默认且有显著标识：页面顶部模式卡片 + 详情页调用统计上的「含模拟调用（N / M 次），不是真实模型结果」标签。§2 命令 8 中 `simulated` 计数等于尝试总数（3/3、5/5），标签必然出现。

### 3.8 提示词协议合规修订（S04-08）

S03 遗留的「记录 4 失败族」里有一种机制是**结构性的**：提示词要求「原样保留换行」，而 JSON 字符串里必须写成 `\n`——两者不点破就会二选一错一个（写进真换行则整个 JSON 无法解析；为避开换行把两行接起来则摘录对不上原文）。本次修订：

- 两份提示词在「摘录怎么选」下新增两条，明确 **「逐字」的判定时点是 JSON 解析之后**、换行写成 `\n`（反斜杠 + n）、引号写成 `\"`；并**禁止改写列表符号**（`-`/`*`/`1.`/`（1）`/`•` 照抄）与**跨行接成一行**。`## 输出` 下各补一句格式提醒。
- `_FEEDBACK_HINTS[KIND_OUTPUT_FORMAT]` 现在点名换行转义（原来只说「只输出一个 JSON 对象」）；`KIND_EVIDENCE_SUBSTRING` 的提示也补上「逐字的判定时点」与列表符号照抄。
- 版本：`stage1_prompt`／`stage2_prompt` `1.1 → 1.2`；**`stage1_schema`／`stage2_schema` 保持 `1.1`，输出契约不变**（§2 命令 9 实测）。批次兼容按「沿用批次快照」处理，不回溯改写历史批次。

**本轮无法自动验证的部分（如实标注）**：提示词改动的**真实效果**只能在真实调用下观察，而 S04 零真实调用——本轮能证明的是**提示词与反馈文本确实包含这些条文**（§2 命令 1 的 6 项提示词用例 + 2 项反馈用例），**不能**证明模型因此 100% 合规。阶段文档已把「只提高合规概率、不承诺 100%、耗时不变短」写进 S04-08 的定稿要点。
