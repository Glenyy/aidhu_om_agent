## 3. 代码与合同核对

### 3.1 适配器（S03-01）

- 使用 OpenAI 兼容 SDK，**`max_retries=0`**：`test_llm_client.py` 对两阶段分别断言 SDK 客户端重试次数为 0，重试只由阶段执行器管理，不叠加。
- **只解析最终内容**：`llm/client.py::_response_of` 只读 `choices[0].message.content`，推理内容不返回、不落盘、不进前端。命令 4 实测 R1 确实同时返回 `reasoning_content`（663 字符）与 `content`（13 字符），该设计与真实响应形状相符。
- 错误分类：408/425/429/5xx 与连接/超时族为可重试；400/401/403/404/422 为不可重试；400 且含 `context` 归为 `ContextLimitError`；`finish_reason="length"` 归为 `TruncatedOutputError`；未知异常保守归不可重试并保留原类型名。全部消息经 `config.redact()` 脱敏。
- 用量缺失时为 `None`，**不用 0 冒充**（`_usage_of` 有对应断言）。
- SDK 客户端**延迟构造**：缺 `base_url`/`api_key` 时抛 `ModelConfigError`（错误码 `CONFIG_INVALID`），只走模拟模式的进程不需要凭据。

### 3.2 请求边界（S03-02／S03-03）

由 `test_stage_messages.py` 以请求捕获断言，不靠界面假定：

- 阶段一消息恰好为 `system` + `user` 两个角色，包含 q 与全部 10 个 ref 槽位（其中 7 个为空资料时带明确空标记），**从不包含 a**。
- 阶段二消息包含 q、a、全部 10 个原始 ref 与**完整的阶段一 JSON**（含 `required_points`、`missing_information`、`conflicts`、证据摘录与原始 `sufficient` 字面值），不是摘要。
- 两阶段使用不同的系统提示词；缺 q（阶段二另含缺 a）时直接拒绝构造请求。
- 命令 5 的真实证据中，6 次调用的角色集合均为 `(system, user)`，与合同一致。

### 3.3 业务规则

- 三分类标签只有 [schemas/judgement.py](../../../../../src/aidhu_om_agent/schemas/judgement.py) 中的 `Label` 三值，`LABELS` 由其导出；`evidence_sufficiency`（sufficient/insufficient/uncertain）是**内部分析值，不是业务标签**，并有 `test_stage1_has_no_business_label_field` 断言阶段一结构里不存在 `label` 字段。
- 阶段一为 `insufficient`/`uncertain` 时**仍进入阶段二**（`test_pipeline.py` 有对应用例）。
- 阶段一原结果保留：阶段二只能写入 `stage1_corrections`，不覆盖 `stage1`。
- 一致性约束：`uncertain` ⇒ 必须复核；要求复核 ⇒ 必须给出复核理由；`answer_correct` ⟂ `insufficient`；`answer_correct` 必须带证据；更正若影响分类 ⇒ 必须复核。
- 输入资料中的文字只作为数据传递，不改变任务（提示词与结构均不含按资料内容改判的路径）。

### 3.4 校验与有限重试（S03-04）

- JSON 提取**只接受**一个完整裸 JSON 对象或恰好一个完整 fenced JSON 代码块；两个候选、自由文本、带前缀、数组、空块一律拒绝，不在多候选中猜测。
- 证据引文必须是所引用 ref 在换行归一化后的**真实子串**；引用范围、必填字段与枚举均校验。
- 校验失败把**简短问题摘要**作为反馈消息追加后重试；每阶段最多 3 次（含首次），退避取自 `execution.retry_backoff_seconds`（默认 2s、4s），由 `test_pipeline.py` 断言实际等待序列为 `[2.0]`；3 次仍不合法记 `OUTPUT_INVALID`。
- 不可重试错误（`MODEL_PERMANENT`/`OUTPUT_TRUNCATED`/`CONFIG_INVALID`）立即失败、**不消耗退避**；预算在**调用之前**登记，耗尽时不发起调用。
- 任何失败**标签留空**；集成测试用真实模式的缺凭据路径实测到 `partial_failed` + `label: null` + `CONFIG_INVALID`。

### 3.5 单条闭环与模拟（S03-05）

- `run_single` 固定顺序：阶段一 → 校验 → 阶段二 → 校验；正常记录**恰好 2 次调用、各 1 次尝试**。命令 5 的 3 条真实样例全部为 2 次调用、`attempt=1`、无重试，与该合同一致。
- 模拟为**确定性合成响应**：用 `zlib.crc32` 选情境，同记录同情境输出完全一致；证据摘录取自真实 ref 因而能通过生产校验；`simulated=True`、`model="mock-deterministic"`、`usage=None`，不经网络。
- 五类情境（回答正确／资料不足／答案错误／重大更正／强制复核）由单测逐个断言，且断言 200 个编号能覆盖全部五类。

### 3.6 真实服务兼容（S03-06）

**调用记账（授权上限 10 次，实际 10 次）**：2 次格式探针 + 2 次因测试自身缺陷中断的流程调用（见 §4 第 1 条）+ 6 次流程调用。

实测事实：

| 事实 | 实测值 |
| --- | --- |
| 服务实际返回的模型标识 | `deepseek-ai/DeepSeek-V3`、`deepseek-ai/DeepSeek-R1`，与配置完全一致 |
| 所发参数是否被接受 | 适配器只发 `model` 与 `messages`（无 temperature/max_tokens/stream），两阶段均被接受 |
| 响应格式可否直接解析 | 可以。`choices` 长度为 1，`finish_reason` 全部为 `stop`（无截断）；R1 的最终答案在 `content`，思考过程在 `reasoning_content` |
| 上下文与输出限制 | **只测得下界**：最大被接受的输入为 2,816 tokens（最长样例的阶段二）。**未探测真实上限**（探测会额外消耗预算） |
| 可用用量 | `prompt_tokens`/`completion_tokens`/`total_tokens` 均可读；另见 `prompt_cache_hit_tokens`（0）与 R1 的 `completion_tokens_details.reasoning_tokens` |
| 耗时 | V3 4.0—14.7 秒；R1 64.5—91.3 秒（最长样例的阶段二 91.3 秒，仍在配置的 300 秒超时内，余量充足） |
| 三条样例的实际标签 | `未检索到正确资料`（L-1）、`回答正确`（L-2）、`检索到正确资料但回答错误`（编号 1），均在既定三分类内 |

**格式兼容与分类准确率分开记录**：以上只证明格式、参数与限制兼容。3 条合成样例上的标签是真实模型输出，但**样本量不足以构成任何准确率结论，也不是质量验收**。

### 3.7 界面骨架（S03-07）

- 单页 [JudgeView.vue](../../../../../src/frontend/pages/JudgeView.vue)（替代 S01 占位页 `HomeView.vue` 的路由位置），四区齐全：常驻模式条、上传与选表、预检结果（覆盖 S02 复验）、判一条。
- 模拟为**默认**模式，页面有多处显著标识；切到真实模式需**二次确认弹窗**并写明会产生费用；结果区在模拟模式下带“模拟结果，非真实模型输出”告警。
- 前端只按后端返回的文本展示标签/状态/证据，**不在页面推导业务标签**（[.claude/rules/frontend.md](../../../../../.claude/rules/frontend.md)）；`pnpm typecheck` 在严格类型下通过。
- 结果区状态行 `任务 …｜状态：…｜当前阶段：…` 的「当前阶段」按后端 `current_stage` 与 `status` **联合**判定（§4 第 10 条）：终态显示「无（任务已结束）」，不会出现 `completed` 搭配「等待中」的自相矛盾。
- 命令 9 用**真实运行的 uvicorn 服务**走通页面会走的全部请求（静态页面与资源、样例下载、上传、预检、判一条、轮询），并核对到上传区 sha256 与预检 `file_sha256` **一致**。
- **未由开发者执行的检查**：浏览器实际渲染与鼠标点击。原因是仓库未安装浏览器自动化依赖（无 playwright），新增依赖超出已批准范围。因此“浏览器中可点击”由用户按手动指南确认，本报告不代填该结论。

### 3.8 凭据与临时性

- 凭据只在后端运行时经 `.env` 读取；配置快照只暴露 `api_key_present`；日志过滤器在落地前脱敏；前端与版本库不含凭据（命令 7、8 实证）。密钥值未写入规则、文档、配置快照、前端或版本库。
- **临时性已显式标注**：上传登记、预检快照与判别任务都保存在**进程内存**，API 进程重启即全部丢失，**本阶段不承诺中断恢复**（属 S04）。阶段文档 §2.3、本报告与手动指南三处均已写明。

### 3.9 界面样例下载（§0.3 追加）

- `GET /api/samples` 返回 5 份样例的名称、文件名、说明与条数；`GET /api/samples/{name}` 现场用 openpyxl 生成 `.xlsx` 返回**文件本体**（非 `data` 封套），带 `X-Request-ID` 与 `Content-Length`；未知名称 404 并列出可用名称。仓库仍**不提交任何二进制 .xlsx**。
- 单测断言每份样例的预检结果与其对外说明**逐项一致**（`blocked` 样例确实被阻断、五情境样例确实覆盖五类情境、最长样例确实最长且含 20 行长资料），防止界面手验时“说明与结果对不上”。
- 发现并处理：同一份样例每次生成的字节**不稳定**（xlsx 内含时间戳，sha256 每次都不同）。因此删除了一开始写的 `digest_of()`/`sample_names()` 两个未被使用的函数，并把界面与指南的核对口径改为**本次上传的 sha256**（上传区显示值应与预检 `file_sha256` 一致），不给出跨次固定的期望值。见 §4 第 2 条。
