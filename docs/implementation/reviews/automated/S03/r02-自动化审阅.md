## 3. 代码与合同核对

### 3.1 R-1 被拒输出留存

- 触发点唯一：`_run_stage` 的 `except ValidationError` 分支写入 `raw_output`，同分支外（成功尝试、模型错误）不写。核对 [agent/pipeline.py](../../../../../src/aidhu_om_agent/agent/pipeline.py)：`raw_output` 仅在该分支被赋值。
- 只看 `response.content`，不读 `reasoning_content`；`result_to_payload` 的**顶层 key 集合不变**（`test_payload_contains_stage_details_and_attempts` 的集合断言仍通过），仅在每个 attempt 字典追加两个键。
- 截断策略：`RAW_OUTPUT_LIMIT = 8000`，保头 6000 + 尾 2000，中间插入省略标记；测试断言首尾字符串保留（尾部正含 JSON 的 `evidence`）。

### 3.2 R-2 错误分类与反馈

- `ValidationError.kind` 默认 `None`，**不参与任何判定**：判定只看是否抛出该异常；未打标的既有调用点行为不变（`test_error_kind_defaults_to_none`）。
- 8 个 `KIND_*` 常量按「给重试反馈选措辞」使用；`_feedback_hint` 未命中即返回通用提示（`test_unknown_validation_kind_falls_back_to_generic_hint`）。
- 反馈文本**保留**原有前缀 `上一次输出未通过校验：{error}。`，`test_validation_error_feeds_the_problem_back_and_retries` 中 `test_pipeline.py:254` 一带的既有断言未改字、只扩展。

### 3.3 R-3 提示词

- 两份提示词的契约句（「必须是对应 ref 的**原文子串**：逐字复制…」）**原句保留**，新增小节追加在其后；新用例 `test_prompt_keeps_the_verbatim_substring_contract`、`test_prompt_tells_the_model_how_to_pick_a_quote` 对两份提示词同时断言。
- 版本：`STAGE1/2_PROMPT_VERSION` 与 `STAGE1/2_SCHEMA_VERSION` 均由 `1.0` → `1.1`；受影响的既有断言仅 `test_stage_messages.py` 两处，已同步改为 `"1.1"`（**改的是断言里的期望值，不是产品代码**）。
- **连带影响（须在 S04 处理）**：按 [plan/02 §5](../../../../../plan/02-架构与详细设计.md)「改提示词须新建批次」，S04 的批次兼容判断要认 `1.1`，旧批次恢复可能被判不兼容。

### 3.4 R-4 耗时与尝试序号

- `JudgeJob` 新增 `created_at` / `started_at` / `finished_at` / `elapsed_ms` / `current_attempt`，`begin()` / `set_stage()` / `finish()` 统一改状态；**成功与失败都落 `finished_at`**，不留 running 悬挂（`test_failure_also_records_finished_at`）。
- `created_at/started_at/finished_at` 对齐 [plan/08 §7](../../../../../plan/08-API接口与数据合同.md) 的 job 字段；`elapsed_ms` / `current_attempt` 是本次新增的**内部扩展**，S03 的 `/api/jobs/{id}` 本就是临时接口，最终契约由 S06 定——已在 [services/judging.py](../../../../../src/aidhu_om_agent/services/judging.py) 的 `payload()` docstring 中写明。
- **尝试序号机制的边界（已写入代码注释）**：包装客户端按阶段自计数，只有「账本从空开始」时才等于阶段尝试序号（当前每次新建内存账本，成立）。S04 换持久化账本后，序号必须改从账本读，否则恢复场景会从 1 重新计数。
- 前端：运行中每秒本地刷新已用时间，终态改用后端最终值并停表；状态行显示「已用 / 第 N 次尝试」，并补一句说明真实模式单次调用可能需要 1 分钟以上、每阶段最多 3 次——直接回应「四分钟没结果像卡死」的观感。

### 3.5 R-5 诊断产物

- 位置：`<config.paths.runtime>/judge-diagnostics/judge-<job_id>.json`；仅在存在非 `ok` 尝试或记录失败时写，干净成功不产生文件（`test_clean_success_writes_no_diagnostic_artifact`）。
- 内容：job 与记录标识、模式、`job_status` / `record_status`（两层状态分开写，避免混淆）、时间与耗时、模型标识、提示词与 schema 版本、failure、每条 attempt 的 outcome/latency/error 与 `raw_output`、以及由 `diagnose_raw_output` 从被拒输出中尽力取出的每条摘录的字符级诊断。
- `diagnose_quote` **只报事实**：是否子串、摘录与原文长度、最长公共子串（含回显，限 200 字符）、相似度、首个分歧位置与该位置的双方字符、原文窗口；**不写推测**（例如不写"疑似去掉了 `**`"）。
- **写盘异常不影响任务状态**：整个函数体包在 `try/except` 中，`test_diagnostic_write_failure_does_not_change_job_status` 通过注入异常验证任务仍为 `partial_failed`、`error` 仍为 `None`、且未产生文件。
- 不含凭据：产物字段全部来自任务与模型输出，凭据只在 `llm/client.py` 运行时读取（本次未改该类代码）。

### 3.6 R-6 模拟失败路径

- `SCENARIO_FORCED_FAILURE` **不加入** `SCENARIOS`，因此 `SCENARIOS[zlib.crc32(seed) % 5]` 的映射与既有五个情境完全不变；`five-scenarios` 样例的编号→情境映射断言（`test_five_scenarios_sample_covers_every_mock_scenario`）继续通过。

### 4.2 一度被报告的分类分歧——已由用户更正为「不成立」（2026-10-06 结案）

**结论先行**：用户于 2026-10-06 更正——该记录**人工金标准应为「未检索到正确资料」**，先前口头告知的「回答正确」是**说错了**；**模型的判别无误，本项不构成分歧，也不构成工程缺陷**。§4.1 的技术结论与本节结论一致，返工在目标问题上达成。

以下保留当时的分析过程，因为它记录了模型行为与规划口径的一致性，可作后续评估集的判读参考。

同一次运行中，模型给出 **`未检索到正确资料` / `资料不足` / 需人工复核：是**，而用户起初说明该记录**人工金标准为「回答正确」**。经开发者只读核对记录 `1` 的全部 10 份资料（`data/runtime/record1_dump.json`），事实如下：

- **ref1—ref10 全部 10 份资料中，没有任何一份说明「如何查询本人的认证时长」**（10 份资料主题各异，涵盖个人事迹、工作总结、办事指南、活动报道等；其中 2 份本身含有时长数字，但均不是查询途径）。

对照 [plan/01 §4 判别口径](../../../../../plan/01-需求与验收标准.md) 第 77 行：「`a 看似合理，但关键结论缺少验证资料` → **暂判未检索到正确资料**，不表述为已证实事实错误 → **必须复核**」。**模型的行为与现行规划口径一致**，且与第 76 行「ref 不足，a 未完成核心回答 → 未检索到正确资料」同向。

过程与更正：开发者当时按「人工金标准「回答正确」」报告为**口径分歧**并列出两条互斥处置路径；用户 2026-10-06 先决定「先搁置、去核实金标准」，随后**核实结论为该标注系口误，正确标注即「未检索到正确资料」**。因此**不需要任何口径修改**（未触及 plan/01 与阶段契约），**也没有人工分类分歧需要记录**。

**证据强度须如实说明**：用户 2026-10-06 说明，其人工标注表里该条**本来就标的是「未检索到正确资料」**，先前口头告知的「回答正确」只是**转述时说错**，并非看到模型理由后才改的标注。因此这次一致是**独立一致**——金标准在模型输出之前就已固定，模型的理由没有反过来影响标注。但**仍不能**作为分类准确率结论：这是**唯一**一条带人工金标准、且已比对过的记录（**n=1**），按 [plan/01 §4 验收](../../../../../plan/01-需求与验收标准.md) 的质量指标口径，分类质量仍需在 S07 用未参与调试的独立保留集评估。标注由用户提供，开发者未参与判定、也未代填。
