## 0. 本轮交付概览

S05 把「判别结果」变成**可交付的文件**，并给命令行补上业务入口：

- 导出四表 xlsx（分类结果 / 复核清单 / 失败清单 / 运行概况）与两阶段 JSONL，**成对发布**；
- 快照在 **worker 认领导出任务时**捕获，因此任意批次状态都能导出，运行概况里写明未处理数；
- 判别终态（`completed`/`partial_failed`）在同一事务里排一条**自动导出**；`failed` 不排（§0.2 第 7 项，用户确认按此执行）；
- HTTP 面：`POST/GET /api/runs/{run_id}/exports`（幂等）、`GET /api/artifacts/{artifact_id}/download`；`run_detail` 填真实 `latest_export` 并新增 `allowed_actions.can_export`；
- 界面：批次详情页新增「导出」区块（导出按钮 → 状态 → 未处理提示 → 历史与下载）；
- CLI：`run`/`resume`/`export` 可用，`--wait` 以退出码 0/4/5 反馈，`evaluate` 只定参数合同。

**S06/S07 明确未做**：记录列表与证据详情、筛选分页、上传生命周期打磨、指标计算（`evaluate` 只到「未实现，将在 S07 提供」）。

## 3. 代码与合同核对

### 3.1 导出字段与编码合同（S05-01）

- 四表列序、JSONL 字段、`序号 1..N`（`order_index` 存储仍为 0 起，导出时 +1）、长文本截断标记 `…【已截断，完整原文见 JSONL】`、公式注入前缀（`=`/`+`/`-`/`@` 开头强制文本）都定义为 `schemas/export.py` 的常量，`test_export_contract.py` 逐项断言。
- **输入资料中的文字不能改变任务**：导出只是把已落库结果写成文件，不重新判别、不补标签；失败与未处理行的原预测与理由留空（`test_exports_document.py`）。
- **不填造**：空标签、未处理、失败三态在四表与 JSONL 中各有明确表示，无默认值兜底。

### 3.2 快照装载与文件生成（S05-02）

- 快照在**一个读事务**里把该批次全部 `records` + `stage_results` + `call_attempts` 载入内存，**结束读事务后**再生成文件；`captured_*` 写回 `exports`。
- 阶段一原结果与阶段二更正**分别保留**，阶段二不覆盖阶段一（JSONL 逐条含 `stage1`/`stage2`）。
- 「运行概况」表含未处理数与被截断单元格的位置；计数与批次口径同源（`services/batches.counts_of`），`test_exports_document.py` 核对计数恒等式。

### 3.3 worker 侧导出与成对发布（S05-03）

- `claim_next_job` 认领范围扩为 classify + export；**判别闸门打开时仍消费导出**，判别任务留在队列里（`test_export_jobs.py::test_paused_dispatch_still_consumes_export_jobs`）。
- **成对发布**：先写临时文件，两份都写完再改名并登记；只有一份成功时不发布半组（`test_export_jobs.py`）。
- **自动导出**：`worker._finalize` 在 `completed`/`partial_failed` 的同一事务里排一条 `source='automatic'`、`scheduled_revision = run.revision` 的导出，靠偏索引 `uq_automatic_export_revision` 去重；`failed` 路径**不排**。手工导出用 `source='manual'`，因此手动导出的 `scheduled_revision` 不会挡住终态那次自动导出。
- **导出失败只标任务自己**：`test_export_jobs.py::test_export_failure_marks_only_the_job` 证明批次状态、分类结果、产物表与判别闸门都不变。
- `export_error_message()` 把异常文本里的 outputs 绝对路径替换为 `<outputs>`、只取首行、截断到 300 字符——这条错误会被 `GET /api/runs/{id}/exports` 发给浏览器，[plan/08 §1](../../../../../plan/08-API接口与数据合同.md) 不允许读接口带本机路径。**第一版实现有缺陷，本轮已修**（§4 问题 9）：`OSError.__str__` 用 `repr()` 拼 `filename`，Windows 路径的反斜杠在字符串里是**两个字符**，只按 `str(path)` 替换在真实的 mkdir/open 失败上永远不命中；现在四种形态（原样／正斜杠／`repr` 转义／转义后正斜杠）都换，并把残留的盘符与 UNC 路径统一换成 `<path>`。回归测试在 `test_export_jobs.py`（真实 `OSError` 造消息，含 `repr` 形态断言）与 `test_api_s05_exports.py`（接口响应断言）。

### 3.4 导出与下载 HTTP 接口（S05-04）

- `POST /api/runs/{run_id}/exports` 要求 `Idempotency-Key`（缺失 422），scope 为 `POST /api/runs/{run_id}/exports`；同键重放返回第一次的 `export_id`/`job_id` 且 `reused=true`，**不排第二份**；同键不同请求体 409 `IDEMPOTENCY_CONFLICT`。
- 同一批次已有导出在飞时 409 `STATE_CONFLICT`；**后端与界面用同一条规则**（`allowed_actions.can_export` / `export_disabled_reason`），不会出现「按钮能点、一点就 409」。
- **任意批次状态都可导出**（含 `failed` 与未跑完的批次），`test_api_s05_exports.py` 覆盖 `queued` 态与 `failed` 态。
- `GET /api/runs/{run_id}/exports` 新→旧返回全部导出（含排队中与失败），`artifacts` 只在 `completed` 时非空。
- `GET /api/artifacts/{artifact_id}/download` 按**登记行**定位文件：`is_relative_to(outputs)` + `is_file()` 双重校验，文件缺失或路径越界一律 404 `ARTIFACT_MISSING`，**不接受用户磁盘路径**；响应用 `artifacts.download_name` 作为文件名。
- `run_detail` 的 `latest_export` 为真实值；`captured_*` 在捕获前为 `null`，界面显示「尚未捕获快照」，**不拿 `scheduled_revision` 冒充已捕获的 revision**。

### 3.5 界面导出面（S05-05）

- `/runs/{run_id}` 新增「导出（Excel + JSONL）」卡片：导出按钮（禁用时显示后端给出的原因）→ 最近一次导出（含「尚未捕获快照」与 `remaining>0` 的未处理警告）→ 失败提示（明说分类结果未受影响、重新导出不覆盖原文件）→ 导出历史表（时间/来源/状态/快照/未处理数/两份文件与下载链接）。
- **轮询**：批次终态后批次轮询停止，只要还有导出在飞就**单独继续轮询导出**，直到两份文件可下载；`onBeforeUnmount` 与 `runId` 变化都会停掉两个定时器。
- 下载走 `<el-link :href>` 由浏览器直接取文件（后端返回文件本体而非 JSON 封套），前端不拼本地路径。
- 类型与「导出属 S06」的旧文案已按 §0.2 第 10 项更新。

### 3.6 命令行入口与等待行为（S05-06）

- `run <xlsx>`：走与网页**同一条服务路径**（上传 → 预检 → 创建批次），**自己不调用模型**；因此**不提供 `--mode`**——执行模式由 worker 启动时决定（`worker --mode mock|real`），把 `--mode` 放在 `run` 上会让人误以为 run 会调用模型。
- `--config` 优先级 `--config > configs/config.local.toml > configs/config.toml`，**只加在新增的 run/resume/export 上**；`serve`/`worker` 仍走 `load_config()` 的原有顺序，未改。`test_cli_s05.py::test_config_precedence_explicit_then_local_then_plain` 用 `source_config` 逐级断言。
- `--wait` 的存活判断复用 `WorkerLock` 的加锁原语（新增 `probe()`：临时加锁后立即退回，**不写归属信息、不留持锁状态**），**不读 `last_activity_at`**（[plan/10 §4](../../../../../plan/10-任务状态与恢复设计.md) 禁止按时间戳猜进程存活）。等待期间只轮询**本命令自己入队的那一个 `job_id`**。
- `--wait` 且没有 worker 时**什么状态都不留下**：`run` 不开库、不上传、不建批次（`test_run_wait_without_a_worker_exits_4_and_leaves_no_state` 断言库文件与上传目录都不存在）；`resume`/`export` 同样先探测后入队。等待中 worker 消失则退出 4，**不改队列状态**（任务留在 `queued`）。
- 退出码：0 成功；2 参数/状态不适用（含 `evaluate` 未实现）；1 配置或环境错误；3 锁被占用（仅 `worker`，沿用 S04）；4 等待时无 worker；5 终态但非成功。**「需复核」标记本身不改变成功状态**。
- **预检 `blocked` 取 1**（§2.1 实测）：与 `inspect` 对同一个预检结果保持同一套退出码——同一个函数 `precheck` 的同一个结论不该在同一个 CLI 里有两个码。这是本轮为 CLI 定的口径，已在 §2.1 记录，供用户复核。
- `evaluate` 只在 argparse 定合同（四个参数在 `--help` 可见），运行到实现处打印「未实现，将在 S07 提供」并返回 2；**没有任何指标计算逻辑**。

### 3.7 未实现范围（不构成本阶段完成条件）

`/api/judge` 仍是临时内存接口（S06 由 runs 记录体系取代）；记录列表与证据详情、筛选分页、上传生命周期与错误合同打磨属 S06；`evaluate` 的指标计算属 S07；导出**不含**人工核定成绩。`outputs/s02_samples/` 与 `data/runtime/interim-export/` 两个历史目录的处理仍待用户决定，未计入本阶段完成条件。

## 5. 交付与人工审阅

**新增/更新产物**：见 §1 表格；`exports`/`artifacts` 数据落到本机 SQLite（结构版本 2 未变），文件落 `outputs/<run_id>/<export_id>/`（`outputs/**` 已被 `.gitignore` 忽略）。

**限制与说明**：

- **本轮零真实调用**；界面导出的内容全部来自模拟模式的判别结果，**不能当作业务分类质量的证据**。
- 导出内容取决于**捕获时**的批次进度：排队期间新判定的记录不进这一份导出；`remaining > 0` 的导出不是「全部判完」的证据。
- `failed` 批次**没有**自动导出（没有可交付结论），但仍可手动导出一份「当前进度」。

**需用户在界面上确认的项**（指南：[r01-手动操作审阅](../../manual/S05/r01-手动操作审阅.md)）：

1. 批次终态后**自动**出现一条 `automatic` 导出，两份文件都能下载，且**下载字节与界面显示的 sha256 一致**；
2. 手动导出可点、导出中显示「尚未捕获快照」、完成后给出两个下载链接；**重复导出不覆盖任何已下载或人工填过的文件**；
3. 「复核清单」的「人工判断」「复核说明」两列可填、另存不影响原文件；
4. **导出失败**（指南 C 组用 `AIDHU_OUTPUTS_PATH` 注入）显示 `failed`、**没有下载链接**、**批次与分类结果不变**，错误信息里**不含本机路径**，重新导出可恢复；
5. 技术失败的记录**没有标签**；未跑完的批次导出时**未处理数在界面与「运行概况」表两处明写**。

**界面外、已由本轮实跑记录的项**：命令行退出码 0/1/2/4/5 与 `--config` 优先级属进程级行为，浏览器看不到；§2.1 已用真子进程逐条实跑（含「没有 worker 时 `--wait` 不留下任何状态」），§2.4 记录了中断态导出，指南 §5 列出结论与界面内的等价现象——**用户无需为验收去跑命令行**。

**结论**：必需检查全部通过，无影响完成条件的问题，**自动化审阅通过、待手动审阅**。用户结论单独记录在 `docs/implementation/reviews/manual/S05/r01-用户审阅结果.md`，本报告不代替用户手动审阅或业务核定。
