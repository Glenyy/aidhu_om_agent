## 3. 代码与合同核对

**输入合同（已实现）**。`INPUT_COLUMNS` 为 `("编号","q","a",ref1…ref10)` 共 13 项，列名常量单点定义，全项目无重复字面量；`INPUT_CONTRACT_VERSION = "1.0"`。表头固定第 1 行，去首尾空白后精确匹配；缺列与重名列分别在**扫描数据行之前**阻断，因此 `counts` 四项保持 `None`，不产生可处理记录。

**计数恒等式（已实现）**。`total` 只计非空记录，空行与仅空白行另计 `skipped_blank_rows`；`valid + input_invalid = total` 在全部 15 个样例上成立（如 partial_failure：1+3=4）。

**失败记录不填造内容（已实现）**。失败记录的 `q`/`a` 保持 `None`，不赋标签、不伪造判断；仍保留 `record_id`、`source_row`、`order_index`（`order_index` 含失败记录连续编号），可按住追踪。仓库中不存在任何业务标签或准确率数据。

**三分类枚举唯一来源（已实现）**。`schemas/judgement.py` 的三个字符串与 `plan/01-需求与验收标准.md` 第 58—60 行逐字一致；`LABELS` 由枚举派生，`validate_label` 只接受这三个值，空值、未知值与非字符串一律拒绝。

**引用位置校验（已实现，且不宣称语义正确）**。`validate_evidence` 要求 `ref_id ∈ ref1—ref10`、`quote` 归一化后非空、且必须是**对应 ref 原文的真实子串**。改写标点、跨 ref 拼接、取自其它 ref 的摘录均被拒绝；`\r\n` 与 `\n` 归一化后一致则通过。`agent/validation.py` 模块文档明确写明校验只证明格式与摘录位置，**不证明语义正确或业务判断正确**——语义充分性属 S03。

**只读性（已实现）**。`precheck` 全程 `read_only=True`；公式单元格存在时才进行第二次 `data_only=True` 读取；两次读取后均 `workbook.close()`。原文件 sha256 前后一致（§2 命令 10）。

**快照可复用（已实现）**。`ParsedInput`/`PrecheckReport` 均为 frozen Pydantic 模型且可 `model_dump` 序列化，S04 落库与 S06 预检接口可直接复用；本阶段不落库。

**未实现（属后续阶段，不计入本阶段通过）**：模型调用与两阶段流程（S03）、SQLite 持久化（S04）、`run`/`resume`/`export`/`evaluate`（S05）、HTTP 上传与预检接口、解压总量与单元格级保护（S06）、导出与评估（S07/S09）。上述能力本阶段**未实现、也未以任何方式宣称通过**。

**超出批准清单但需披露的两处实现决定**（均在本阶段边界内，请用户在手动审阅时一并确认）：

1. **新增 blocker `DUPLICATE_COLUMNS`**。§2 S02-02 列举的阻断项为 5 类，实际实现为 6 类：表头出现重名列时列映射有歧义，故阻断（如 `q` 列出现两次）。若按位置取列会静默读错列，因此选择阻断而非忽略。
2. **不可读的 ref 单元格记 input_invalid**。§2 S02-03 只写明「编号/q/a 缺失或不可读」记 input_invalid，并规定「ref 为空合法」。实现把 Excel 错误值（`#N/A`、`#VALUE!` 等）与**无缓存值的公式单元格**列为不可读，同样记 input_invalid，而不是当作「资料为空」。理由：这类单元格不是「用户没提供资料」，而是「资料在文件里读不出来」，若静默当作空 ref 会掩盖输入缺陷。

**一处命名观察（未修改）**：显式指定 `--sheet 名称` 而该表不存在时，沿用 blocker 码 `SHEET_AMBIGUOUS`（消息文字已准确说明「工作簿中没有工作表 X；实际工作表：…」）。因批准清单固定为 5 类 blocker 码，未新增码，此处仅记录供后续确认。
