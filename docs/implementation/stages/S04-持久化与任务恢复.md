### 0.3 技术定稿（随步骤一并审阅）

1. **不引入任何新依赖**：SQLite 用标准库 `sqlite3`，worker 独占锁用标准库文件锁；**不引入 Alembic 等迁移工具**。
2. **迁移方案自建**：`storage/migrations/001_init.sql` + `schema_migrations(version, script_sha256, applied_at)`；启动时检查结构版本，拒绝读取未来版本，迁移在 worker 消费前串行执行；**迁移前自动备份**到 `data/backups/`（时间戳文件名，不自动删除）。
3. **连接与事务约定**：每个 API 操作与 worker 各用独立连接，不跨进程共用；每连接显式开启并验证 `PRAGMA foreign_keys=ON`；启用 WAL；配置有限 `busy_timeout`；写事务显式 `BEGIN IMMEDIATE` 后及时提交/回滚，不与隐式事务混用（[plan/09 §7](../../../plan/09-数据库与持久化设计.md)）。
4. **`uploads` 与 `input_validations` 一并落库**：`runs` 有 `upload_id`/`validation_id` 外键，「重启后批次仍可用」也要求预检快照可重建。**这是对 S03 内存实现的替换，HTTP 接口形状不变**（S03 验收的是界面行为，接口未变）。
5. **`record_key` 为内部 UUID 主键**，业务编号另存 `record_id` 并加部分唯一索引 `uq_run_record_id`；`q`/`a` 只在 `input_invalid` 行允许为空。
6. **pipeline 不直接写库**：扩展现有 `BudgetLedger` 协议（[agent/pipeline.py:113](../../../src/aidhu_om_agent/agent/pipeline.py#L113)）为「预算 + 占位/提交回调」，由服务层注入 SQLite 实现；`run_single` 的两阶段逻辑与 S03 行为不变，单测继续用内存实现。
7. **`current_attempt` 改从账本读**，不再靠 `_ReportingClient` 计数（该包装器仅在账本从空开始时成立，[services/judging.py:52-58](../../../src/aidhu_om_agent/services/judging.py#L52-L58) 已注明）。
8. **S03 的临时 `/api/judge` 保留但不落库**，继续标注为临时接口，S06 由 `/api/runs/{run_id}/records/{record_key}` 体系取代；S04 的持久化边界因此保持干净。
9. **幂等键纳入 S04**（`idempotency_keys` 表已由 [plan/09 §5](../../../plan/09-数据库与持久化设计.md) 设计）：创建批次与恢复都会产生模型调用，重放风险最大；上传与预检不要求该请求头。
10. **`raw_output` 落本地库、不进 API 契约**：`call_attempts.final_content` 本就是 [plan/09 §4](../../../plan/09-数据库与持久化设计.md) 设计的字段；是否经 API 暴露由 S06 定。写入内容仅最终 `content`、非推理链、仅失败尝试需留存的那几次。

### 0.4 已知风险（须在实现中验证，不靠假设）

- **预检快照能否无损重建 `ParsedInput`**：`POST /api/runs` 要从 `input_validations` 的持久化数据重建解析结果。若 S02 的预检 JSON 不足以重建，S04-02 需追加记录级快照。**这是 S04-02 的显式验证项**。
- **Windows 上的 worker 独占锁**：`fcntl` 不可用，需用 Windows 可用的文件独占锁并实测「第二个 worker 被拒绝、第一个退出后可再获取」。
- **`interrupted` 只在获得锁之后出现**：按 [plan/10 §4-§5](../../../plan/10-任务状态与恢复设计.md)，旧 `running` 任务由**新 worker 取得独占锁后的启动恢复检查**标记为 `interrupted`。手动指南与界面提示必须按此顺序描述，否则会被误读为「恢复没生效」。
- **模拟响应无延迟**：现有 `MockClient` 的 `latency_ms = 0`（[agent/mock_samples.py:248](../../../src/aidhu_om_agent/agent/mock_samples.py#L248)），因此 S04-07 的慢速样例是制造中断窗口的必要条件，不是可选装饰。
- **⑤ `order_index` 起点：规划文字与已接受实现不一致（S04-01 实现时发现）**。[plan/09](../../../plan/09-数据库与持久化设计.md) 第 46 行写「order_index 为非空输入记录顺序（从 1 开始）」，但已验收的 S02 实现是 **0 起**：[schemas/qa.py:108](../../../src/aidhu_om_agent/schemas/qa.py#L108) 为 `Field(ge=0)`，[excel/reader.py:297](../../../src/aidhu_om_agent/excel/reader.py#L297) 为 `order_index = len(records)`；API 与界面返回的也是该值。**处理**：S04-01 按**实际合同**建表（`CHECK (order_index >= 0)`），**不在存储层做静默 +1 平移**（平移会让库与 API 两套口径）。改回 1 起等于修改已接受阶段的可见行为，需用户明确决定，属于本阶段范围外的契约变更。**待用户确认**：维持 0 起并同步修订 plan/09 该行文字，或改为 1 起并相应更新 S02/S03 的输入合同与已接受报告。

## 1. 阶段目标与边界

输入/配置/提示词快照与阶段结果持久化，唯一 worker 串行执行任务，中断及预算行为可验证；并在前端界面上可核对（批次创建、进度、恢复、重启后仍在）。

**边界**：

- 导出任务的**排队与发布接口**在本阶段留出口，实际文件生成到 S05；没有文件时不登记假产物。S04 结束时 `exports`/`artifacts` 表可存在但界面不提供下载（S06）。
- 网页到 S06 才补齐完整交互；S04 只交付 §0.1 定义的**最小批次面**。
- S03 遗留失败族只做**提示词与重试反馈**层面的修订，**不改契约**（不放宽逐字子串判定、不做解析期清洗）；后两者属改契约，须另呈方案。
- 真实模型调用为零（§0.1）。

## 4. 阶段结束需生成的手动操作审阅文档（界面路径）

指南至少覆盖：

4. **重启 `serve` 后强刷 `/runs/{run_id}`**：批次、记录、计数、`revision` 仍在——这是本阶段持久化的核心可核对证据。
5. 上传 `synthetic-slow-batch.xlsx` → 运行中停掉 worker → **重启 worker**（顺序不可颠倒，见 §0.4）→ 界面显示 `interrupted` → 点「恢复」→ 核对调用统计证明**阶段一未被重复调用**。
6. 用户结果填写表（**不代填**）、反馈要求、停止/恢复说明。

### 4.3 界面外检查（单列小节，写明原因与替代证据）

| 检查 | 为何无法界面化 | 界面内可核对的替代证据 |
| --- | --- | --- |
| 启动第二个 worker 被明确拒绝 | 是进程级 CLI 行为：退出码与错误消息只出现在终端 | 第一个 worker 的锁持有期与第二个进程的退出；界面侧核对批次未被两个执行者重复消费（调用统计不翻倍） |
| 中断注入（停 worker） | 需要真实终止进程才能产生未提交状态 | `run.status` 由 `running` 变 `interrupted`、恢复后变 `completed` |
