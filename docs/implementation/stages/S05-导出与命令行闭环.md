### 0.2 技术定稿（随步骤一并审阅）

1. **不引入任何新依赖**：Excel 生成用已在 `requirements.txt` 的 `openpyxl`，下载用 FastAPI 自带的 `FileResponse`。
2. **导出目录**：沿用配置里**已有但至今无人使用**的 `paths.outputs`（默认 `outputs/`，可用 `AIDHU_OUTPUTS_PATH` 覆盖），落到 `outputs/<run_id>/<export_id>/`，与 [plan/05 §2](../../../plan/05-交付与运行指南.md)、[plan/09](../../../plan/09-数据库与持久化设计.md) 一致。`outputs/**` 已被 [.gitignore](../../../.gitignore) 忽略。
3. **快照捕获时机**（[plan/10 §8](../../../plan/10-任务状态与恢复设计.md)）：在 **worker 认领 export job 时**捕获，不是在用户点击时。用**一个读事务**把该批次全部 `records` + 对应 `stage_results` + `call_attempts` 载入内存，**结束读事务后**再生成文件；排队期间新产生的分类结果不影响已捕获内容。`captured_revision`/`captured_at`/`captured_run_status`/`captured_counts_json` 写回 `exports`。
4. **成对发布**：先写临时文件，**两份都写完并关闭**后重命名为最终文件，再在**一个写事务**内登记两条 `artifacts`（`kind` 为 `excel`/`jsonl`）并把 job 置 `completed`。**只有一份成功时不发布半组**；文件写好但登记前中断，按 [plan/09](../../../plan/09-数据库与持久化设计.md) **保留并在启动恢复中记录，不自动删除、不当作可下载结果**，再次导出用新的 `export_id`。
5. **导出失败不改分类结果**：export job `failed` 只改变导出任务状态，**不通过 classify resume 重跑**（[plan/10 §7—§8](../../../plan/10-任务状态与恢复设计.md)）。
6. **worker 认领范围扩大**：`repositories/jobs.py` 的 `claim_next_job` 从「只认领 `kind='classify'`」扩为 classify + export；**判别被暂停（`model_dispatch_paused`，如认证故障后）时仍消费 export 任务**（[plan/10 §7](../../../plan/10-任务状态与恢复设计.md) 明确要求）。导出任务不占 `uq_active_classification`（该索引只约束 classify）。
7. **自动导出的入队点**：`worker._finalize`（completed/partial_failed）同事务入队 `source='automatic'`、`scheduled_revision = run.revision` 的 export job。**`failed`（系统性阻断）路径不自动入队**——批次尚未跑完，用户应先修复再恢复；此时仍可手动导出（§0.1 第 6 项）。**2026-10-07 用户确认：按此方案执行**（原话「failed 自动导出根据你的方案来」）。
8. **幂等**：`POST /api/runs/{run_id}/exports` 要求 `Idempotency-Key`，scope 沿用现有风格 `POST /api/runs/{run_id}/exports`（参照 [services/batches.py](../../../src/aidhu_om_agent/services/batches.py) 的 `RUN_CREATE_SCOPE` / `_resume_scope`）；缺失请求头返回 422 `PARAM_VALIDATION`。
9. **下载接口**：`GET /api/artifacts/{artifact_id}/download` 校验该 artifact 属于一个**已 completed** 的 export job；文件缺失返回 404 `ARTIFACT_MISSING`（**不当作空文件下载**）；响应使用 `artifacts.download_name`；**不接受用户磁盘路径**。`api/routes/artifacts.py` 目前是占位且**未在 [api/app.py](../../../src/aidhu_om_agent/api/app.py) 注册**，本阶段注册。
10. **三处「有意修改」而非回归**（改动了 S04 已验收的可见行为，须在报告中单列）：
    - [services/batches.py](../../../src/aidhu_om_agent/services/batches.py) 的 `run_detail` **硬编码 `"latest_export": None`**，改为返回真实导出概况；
    - [tests/integration/test_api_s04_reads.py](../../../tests/integration/test_api_s04_reads.py) 中**断言 `latest_export is None`** 的用例需随新合同更新；
    - 前端 [types/api.ts](../../../src/frontend/types/api.ts) 把该字段类型写成**字面量 `null`**，需放开；[RunsView.vue](../../../src/frontend/pages/RunsView.vue) 的「导出属 S06」文案需改。
11. **`allowed_actions` 增补 `can_export`**（含禁用原因），供界面按钮使用；后端提交时仍重新检查（[plan/10 §6](../../../plan/10-任务状态与恢复设计.md)）。
12. **CLI 退出码表**（新增 `EXIT_NO_WORKER = 4`、`EXIT_JOB_UNSUCCESSFUL = 5`）：

    | 码 | 含义 |
    | --- | --- |
    | 0 | 成功（判别/导出到达 `completed`；**需复核标记本身不改变成功状态**） |
    | 1 | 配置或环境错误 |
    | 2 | 参数错误；`evaluate` 未实现时的提示 |
    | 3 | 已有 worker 持有独占锁（仅 `worker` 命令，沿用 S04） |
    | 4 | `--wait` 时检测到没有 worker 在跑 |
    | 5 | 任务到达终态但非成功（`partial_failed` / `failed` / `interrupted`） |

13. **`--wait` 的探测方式**：复用 `worker.WorkerLock` 的加锁原语，新增一个**只探测、不写归属信息**的方法（临时加锁后退回），**不依据 `last_activity_at` 判断进程存活**（[plan/10 §4](../../../plan/10-任务状态与恢复设计.md) 禁止）。等待期间按固定间隔轮询该 job 状态，只等待**本命令自己入队的那个 job_id**。
14. **`evaluate` 只定契约**：本阶段在 argparse 中定义 `--run-id`、`--gold`、`--split-manifest`、`--split` 四个参数并在 `--help` 中可见，运行到实现处打印「未实现，将在 S07 提供」并返回 2；**不写任何指标计算逻辑**（属 S07）。
15. **导出产物内容骨架**（S05-01 落地为 schemas 定稿）：
    - **分类结果**：序号(1..N)、原始编号、来源行、原预测、理由、证据、需复核、处理状态；失败/未处理行原预测与理由留空，不填造标签。
    - **复核清单**：序号、原始编号、来源行、q、a、ref1—ref10、原预测、理由、证据、需复核、**人工判断**、**复核说明**（后两列为独立人工填写列，留空；**人工复核文件不回读、不覆盖原预测**）。
    - **失败清单**：序号、原始编号、来源行、失败阶段、错误码、错误信息、尝试次数、是否可重试。
    - **运行概况**：批次标识与来源文件、工作表、输入摘要、批次状态、捕获时间与 `captured_revision`、捕获时状态与计数（含**未处理数**）、被截断单元格数与位置、程序/规则/提示词/schema/输入合同版本、本次导出的两个文件名与 sha256。
    - **JSONL**：每条记录一行，含 export_id、run_id、序号、record_key、record_id、source_row、order_index、q、a、refs、status、label、review_required、理由与证据、stage1、stage2、failure、attempt_summary、版本；**两阶段原始结果与阶段二更正分别保留，阶段二不覆盖 stage1**；**编号不因过滤、重试或恢复而变化**。

## 1. 阶段目标与边界

实现四工作表 Excel、两阶段 JSONL 和命令行批处理，使输入、执行、恢复、导出形成可操作的闭环；**并在前端界面上可核对**（发起导出、看到导出任务状态与历史、下载两份文件）。

**边界**：

- 本阶段不做记录列表、证据详情、筛选分页与上传生命周期打磨（S06）；导出区块只到「能发起、能看到状态与历史、能下载」。
- 不计算正式分类成绩；`evaluate` 只确定参数合同与帮助说明，计算逻辑在 S07，未实现时明确报错。
- CLI 通过共享服务排队，由唯一 worker 执行，**不绕开队列自行消费**。
- **全程零真实模型调用**（§0.1）。

### 2.1 S05-05 界面清单（用户验收路径）

**保留**：既有 `/` 单页「上传 → 预检 → 判一条」、`/runs` 批次列表、`/runs/{run_id}` 批次详情（状态、计数、进度、任务、调用统计、失败摘要、恢复面板）。

**新增到 `/runs/{run_id}` 的「导出」区块**：

1. **「导出」按钮**——点击后入队一份手动导出（`source='manual'`），沿用现有幂等请求头做法；任意批次状态都可点（§0.1）。
2. **导出任务状态**——当前/最近一次导出 job 的 `job_status`、`captured_at`、`captured_revision`、`captured_run_status`；`captured_*` 未到时为 `null` 并显示「尚未捕获快照」。
3. **未处理记录提示**——`captured_counts` 里 `remaining` 不为 0 时在区块内明示，**不把该导出当作完整成功批次**。
4. **导出历史列表**——每次导出一行：时间、来源（automatic/manual）、状态、两份文件的 `download_name`、`size_bytes`、sha256 前缀；`completed` 的行给出两个下载链接；`failed` 的行给出错误码并说明**分类结果未受影响**。
5. **失败导出不提供下载**，只提示「重新导出会产生新文件，原文件与人工已改文件不被覆盖」。
6. **轮询**：批次进入终态后停止批次轮询，**若导出未完成则导出区块继续单独轮询**，直到两份文件可下载（§0.1）。
7. `/runs` 列表页的「导出属 S06」文案同步更新；`/runs` 仍不做筛选分页（S06）。

**S06 仍保留**：记录列表与证据详情、筛选分页、上传生命周期与错误合同、完整任务/产物历史打磨、深链接与幂等交互打磨。

### 4.3 界面外检查（单列小节，写明原因与替代证据）

| 检查 | 为何无法界面化 | 界面内可核对的替代证据 |
| --- | --- | --- |
| CLI `run`/`resume`/`export` 与 `--wait` 退出码（0/4/5） | 是进程级行为：退出码只出现在终端 | 界面批次状态与导出状态的对应变化；`--wait` 无 worker 时退出码 4 的文案 |
| `--config` 优先级 | 是进程启动参数 | 配置快照里的路径与非敏感参数在界面 `versions`/`model_config` 区域可核对 |

| 两份文件在工作区磁盘上的字节与 sha256 | 浏览器只给下载 | 界面导出区块显示 `download_name`/`size_bytes`/sha256 前缀，可与下载后本地计算值比对 |
