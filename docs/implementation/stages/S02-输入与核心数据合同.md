| 决定项 | 结论 | 依据 |
| --- | --- | --- |
| 解析入口 | **新增只读 CLI 子命令** `python -m aidhu_om_agent inspect <xlsx> [--sheet NAME]`，输出预检 JSON；不写库、不调模型 | 用户选择（手动审阅需要可复制的真实命令） |
| 编号归一化 | 数字型 → 去 `.0` 的字符串（7 → `"7"`）；文本型 → 去首尾空白后**原样保留**（`"007"` 仍是 `"007"`）；空/仅空白 → 编号缺失 | 用户选择；符合 plan/01「原编号用于关联结果，不重新编号」 |

| 保护值范围 | S02 校验**文件大小**（`limits.max_upload_bytes`，50 MiB）与**记录条数**（`limits.max_records`，1000）；解压总量、单元格与工作表级保护留 S06 上传层 | 用户选择 |
| 输入合同版本 | 新增常量 `INPUT_CONTRACT_VERSION = "1.0"`（当前代码库无此常量，plan/08 §3 与 plan/09 表结构已引用该字段） | 本文件定稿 |
| 表头匹配 | 固定第 1 行；列名去首尾空白后**精确匹配**，不做同义列名、大小写宽松或模糊匹配 | plan/01 §2 只定义 13 个列名，无同义约定 |
| 行号基准 | `source_row` 为 Excel 1-based 行号（表头行计为第 1 行）；`order_index` 按工作簿顺序连续编号，**含失败记录** | 失败记录需按来源行追踪（plan/01 §2） |
| 持久化边界 | S02 **不写 SQLite**；解析快照为可序列化对象，落库在 S04、预检接口在 S06 | S02 §1 边界 |
| 原文件 | 只读；不新增判断列、不改写、不截取内容；完成后原文件 sha256 不变 | plan/01 §2、plan/08 §3 |
| 公式单元格 | 以 `data_only=True` 读取缓存值；无缓存值（未经 Excel 计算保存）视为不可读，记 input_invalid | 避免把公式字面量当资料文本 |

## 1. 阶段目标与边界

可读取无标签 Excel，产出可追踪的有效/输入失败记录和固定十个 ref，并提供后续流程使用的基础类型。

不做意图检测、不引入重新检索；阶段一/二的详细响应结构在 S03 讨论。这里只形成解析快照和摘要，SQLite 持久化到 S04。

## 2. 可实施小步骤（本轮讨论定稿，待批准）

以下为讨论后定稿的具体内容。经用户批准覆盖的步骤方可进入实现；未覆盖步骤保持待审阅。

### S02-01 明确输入规范和解析版本

| 项 | 内容 |
| --- | --- |
| 具体行为 | 1）定义 `INPUT_CONTRACT_VERSION = "1.0"`。2）集中定义列名常量：`ID_COLUMN = "编号"`、`Q_COLUMN = "q"`、`A_COLUMN = "a"`、`REF_FIELDS = ("ref1", …, "ref10")`，全项目不重复字面量。3）表头固定第 1 行，去首尾空白后精确匹配。4）实现编号归一化（按 §0 决定）。5）实现 `normalize_text()`：`\r\n` / `\r` → `\n`，去首尾空白，中间空白不动。6）数字型编号在 warnings 中提示“前导零可能已由 Excel 丢弃”，因为该信息在单元格存为数字时已不可恢复。 |
| 主要位置 | src/aidhu_om_agent/schemas/qa.py、src/aidhu_om_agent/excel/reader.py |
| 验证方式 | 单测固定三种编号形态（数字 7、文本 `"007"`、空白）、13 列齐全与缺列的表头、`\r\n` 文本归一化；断言归一化后编号与原文用于关联 |
| 完成条件 | 列名与版本常量集中定义；编号规则在数字/文本/空三种情况有单测固定；解析不修改原文件 |

### S02-02 实现工作表和批次预检

| 项 | 内容 |
| --- | --- |
| 具体行为 | 1）工作表选择顺序：显式 `sheet_name` → `QA_REF` → 唯一可见工作表 → 否则 blocked，并报告全部工作表名与可见性。2）读取前校验文件大小 ≤ `limits.max_upload_bytes`，超限直接 blocked，不读取内容、不截取。3）阻断项 blockers：缺必要列（列出缺失列名）、编号重复（列出编号及全部来源行）、工作表无法确定、记录数 > `limits.max_records`、无有效记录。4）输出 counts：`total`、`valid`、`input_invalid`、`skipped_blank_rows`；可统计时 `total = valid + input_invalid`，空行另计。5）输出 warnings：额外列未使用、数字型编号前导零提示。 |
| 主要位置 | src/aidhu_om_agent/excel/reader.py、src/aidhu_om_agent/config.py（只读 limits，不新增配置项） |
| 验证方式 | 单测：无 `QA_REF` 的单表/多表工作簿、显式指定与自动选择、缺列、重复编号、超大小、超条数（用小 `max_records` 配置构造而不造千行文件）、额外列 warning |
| 完成条件 | 上述阻断与统计可用单测逐项复现；超限不产生部分解析结果；blockers 含具体位置 |
| 边界 | 不实现 HTTP 上传、解压总量与单元格级保护（留 S06） |

### S02-03 实现逐行读取和部分失败

| 项 | 内容 |
| --- | --- |
| 具体行为 | 1）13 个输入字段全为空或仅空白 → 跳过，计入 `skipped_blank_rows`，不构成记录。2）编号缺失、q 缺失/不可读、a 缺失/不可读 → 生成 `input_invalid` 记录，保留 `source_row` 与 `order_index`。3）失败记录的 q/a 保持缺失，**不填造内容、不赋标签、不伪造判断**。4）ref 单元格为空合法；ref1—ref10 全空仍为有效记录（资料不足属 S03 业务判断）。5）额外列忽略，不进 `QARecord`、不传后续阶段。6）公式单元格按 §0 决定处理；不可读值归 input_invalid 并给出可读原因。 |
| 主要位置 | src/aidhu_om_agent/excel/reader.py、src/aidhu_om_agent/schemas/qa.py |
| 验证方式 | 单测：空行、仅空白行、缺编号、缺 q、缺 a、空 ref、全空 ref、额外列、公式无缓存值；断言 `valid + input_invalid = total` 且空行另计 |
| 完成条件 | 统计恒等式成立；每条记录与失败项都能定位到来源行；本阶段模型调用次数为 0 |
| 边界 | 不做业务标签、不做资料充分性判断（S03） |

### S02-04 实现基础结构与引用位置校验

## 3. 阶段完成条件

13 列输入及失败统计可解释全部行；编号/原文/ref 顺序保留；输入阶段模型调用为零；引用位置检查有效。

步骤开发完成后自动执行以下审阅，保存 reviews/automated/S02/r01-自动化审阅.md。命令必须在实际开发时验证后填写；不能把尚未安装工具或未实现测试标为通过。

- 验证缺列、重复、多工作表、空引用、全空行、缺 q/a/编号及保护限制。
- 核对 valid + input_invalid = total、空行另计、来源行和原编号不丢失。
- 验证引用真实子串与标签枚举；输入/引用校验不宣称语义判断正确。
- 复验 S01 已有关键行为（配置、路径、脱敏、22 项单测、前端类型检查与构建），检查本阶段是否引入回归。
- 核对本阶段未产生模型调用、未创建 SQLite、未改写原文件。

自动化审阅发现问题，在已批准范围内修复并复审；扩大范围前更新具体方案。报告通过后状态为“待手动审阅”，不代替用户接受。
