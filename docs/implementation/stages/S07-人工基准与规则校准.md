### 0.3 开发者技术定稿（供用户审阅，非用户决定）

1. **标签合同**：`人工判断` 只允许三个中文字符串（回答正确／未检索到正确资料／检索到正确资料但回答错误）；被排除的行 `人工判断` 留空且 `排除理由` 必填；未核定（三值与排除均空）的行视为错误输入。
2. **早期调试样本强制入校准集**：S03 期间在真实模式下用于调试的编号（记录 `1`、`4`）**强制归入校准集**，不进保留集。后续人工指定的调过编号同样强制入校准集。
3. **编号一致性校验**：`evaluate` 校验「批次记录编号集合」与「划分清单中指定 split 的编号集合」逐一同构，不一致即退出码 `2`——这是防保留集泄漏的主要技术闸门。
4. **计分口径**：只评 agent 原预测 `records.final_label`；需复核记录**参与评分、不剔除**；人工修订**不计作** agent 预测。
5. **零分母与不完整**：分母为 0 的指标记「不可计算」（**不记通过**）；技术失败与缺失预测**单独报告、不进混淆矩阵**；有效记录分类完成率未达 100% 时总体验收不通过。
6. **落库与报告**：评估结果落 SQLite 两张新表（`evaluations` 主表 + `evaluation_records` 逐条对照），页面读库；报告同时落盘 `data/evaluation/reports/`（JSON + 文本）。
7. **划分可复现**：同 `seed` + 同 gold 版本 → 同划分；子集 xlsx 用 openpyxl 现场生成（沿用 `excel/samples.py` 的写法，**不新增依赖**）。
8. **冻结清单内容**：提示词版本、schema 版本、模型配置快照、gold 版本与 sha256、划分清单 sha256、冻结日期。
9. **split 名称**：`calibration` 与 `holdout`。

## 1. 阶段目标与边界

建立人工核定基准、固定校准/保留集划分和可验证评估工具，仅用校准集调整规则并冻结待验收版本。

正式业务 Excel 不需要判断列。带人工标签的数据只用于评估，原有初标可参考但由人工确认或纠正。不得由模型自造标准答案；本阶段不使用保留集模型结果调试，不实现日常人工复核结果回读。

**保留集在本阶段一次都不跑**（[plan/04](../../../plan/04-测试与质量评估.md) §2「不从验收集临时挑题调试」）。本阶段的校准成绩**不代替**保留集验收——正式质量结论属 [S08](S08-保留集验收与工程回归.md)。

### S07-01 人工核定数据合同、校验器与核定记录

- **用户产出**：`data/evaluation/gold-v1.xlsx`（工作表沿用 `QA_REF`），列为 13 列输入原件 + `人工判断`／`人工理由`／`关键ref`／`是否排除`／`排除理由`；文件另附核定元数据（数据版本、核定人、核定日期、原始文件 sha256 前 12 位）。
- **开发者产出**：格式合同与 `evaluation/gold.py` 读取/校验实现——编号非空且唯一、与原始批次编号集合同构、标签合法、排除行有理由、元数据齐全；校验失败给出可操作提示。
- **交付与验证**：一个合法的合成 gold 样例入库供测试（**合成数据，不含任何真实问答**）；真实核定文件**只在 `data/evaluation/` 本地存在，不入库**。
- **人工职责边界**：逐条核定的工作由用户完成，开发者只提供合同、校验与记录工具；指南明确这条边界。

### S07-02 固定分层划分与子集生成

- 按 plan/04 §2 固定：种子 `20261005`、校准约 20 条、其余为保留集、按核定三类比例**最大余数分配**、每类校准 ≥1／保留 ≥5；凑不齐数量与类别要求时**报错并提示补数据**，**不缩分母、不改门槛**。
- 强制规则：§0.3 第 2 条的编号强制入校准集。
- 产物：`data/evaluation/split-v1.json`（`seed`、gold 版本与 sha256、`counts`、`assignments`、`forced_calibration`、生成时间）+ `calibration-v1.xlsx`／`holdout-v1.xlsx`（按编号过滤的 13 列原件）。
- 可复现性测试：同输入两次生成结果逐字一致。

### S07-03 指标计算、`evaluate` 实现与评估落库

- `evaluation/metrics.py`：混淆矩阵（**行 = 人工真值、列 = agent 预测**）、逐类 TP/FP/FN/精确率/召回率/F1、Macro-F1（三个 F1 的算术平均）、非正确类误判正确率、总体一致率、分类完成率、复核比例；**每项同时给分子与分母**，零分母记「不可计算」。
- `evaluate` 实现（参数保持现有四个，**零模型调用、不依赖 worker**）：读批次原预测 + gold + 划分清单 → 过 §0.3 第 3 条的编号一致性闸门 → 计算 → 落库 + 落盘报告 → 退出码 `0`／`1`／`2`。
- 报告内容按 plan/04 §6：数据版本、核定过程、排除/划分清单、运行版本、原预测、总体与逐类指标、混淆矩阵、复核率、失败率、阶段更正、调用尝试及耗时。
- 测试：手算小矩阵对照（plan/04 `E-17`）；零分母展示；编号不一致、批次未终态、技术失败与缺失预测各自的报告分支。

### S07-04 校准并冻结规则版本

- 在**校准集**上跑真实模型批次 → 分析误判与原始 ref → 修订规则/提示词 → 冻结。**保留集全程不跑。**
- 允许修改范围：提示词与规则层面的修订（提示词版本按[阶段规则](../../../.claude/rules/development-workflow.md)递增，如 `1.2 → 1.3`）；**不改业务三分类合同、不改 schema 字段语义**。
- 产物：`data/evaluation/calibration-report-v1.md`（误判明细、修改依据、修改前后对比）+ 冻结清单（§0.3 第 8 条）。
- **前置授权**：本步骤的**真实调用预算仍待用户另行授权**（§0.1 未定项）。授权前本步骤不启动。

## 2.1 界面验证面（用户验收路径）

**新增只读评估页 `/runs/:runId/evaluation`**，并在批次详情页加「评估」入口。页面**只读**：不触发计算、不调用模型、不编辑标签。可选核对内容包括：

1. **划分清单与每类数量**：种子、gold 版本、校准/保留各自的三类条数、被排除的编号与理由。
2. **混淆矩阵**：行 = 人工真值、列 = agent 预测，合计与样本数一致。
3. **逐类指标**：每类 TP/FP/FN、精确率/召回率/F1，每项带分子与分母。
4. **达标判定**：非正确类误判正确率 ≤5%、Macro-F1 ≥0.80 两条各自「达标／未达标」；分类完成率、复核比例、技术失败分别显示。
5. **逐条对照**：编号、人工标签、agent 原预测、是否一致、是否需复核、是否被排除；可按 split／是否一致／状态筛选与分页。
6. **冻结版本与校准记录**：§0.3 第 8 条的清单内容，以及校准修订条目（可展开看依据）。
7. **评估历史与报告下载**：同一批次多次评估的列表与报告文件。

**界面外检查（指南中单列）**：`evaluate` 的退出码契约、`split-v1.json` 内部结构、`SCHEMA_VERSION 3` 迁移与备份——这些无法界面化，指南给出可核对的证据位置。

**配套改动**：[plan/08](../../../plan/08-API接口与数据合同.md) 第 47 行改写为「计算入口仍只有 CLI；新增**只读**评估展示页，不提供网页计算或标签编辑入口」，并在接口总表补三条新接口（`GET /api/runs/{run_id}/evaluations`、`GET /api/evaluations/{evaluation_id}`、`GET /api/evaluations/{evaluation_id}/records`）。

- 核对界面验证面（§2.1）实际可用：只读、无计算入口、无标签编辑入口；并核对结构迁移与备份。
