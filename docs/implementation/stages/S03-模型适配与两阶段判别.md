### 2.1 逐步骤定稿方案

**S03-01 模型适配器。** 基于已安装的 `openai>=2,<3`（OpenAI 兼容协议），按 `config.py` 已有的 `ModelConfig`（`base_url`/`model`/`timeout_seconds`/`api_key_env`）构造客户端，**`max_retries=0`**，重试只由阶段执行器管理，避免叠加。提供 `call_model(messages, stage) -> ModelResponse`，`ModelResponse` 含 `content`、`model`（服务实际返回的模型标识）、`usage`（缺省为 `None`，不用 0 冒充）、`latency_ms`、`finish_reason`。**只取最终回答**：响应若同时含推理内容与最终内容，仅解析最终内容，推理内容不落盘、不返回前端。错误分类写入 `llm/errors.py`：可重试（网络、超时、429、5xx）`RetryableModelError`；不可重试/系统性（认证失败、模型不存在、必要参数非法）`PermanentModelError`；`ContextLimitError`（输入超限）与 `TruncatedOutputError`（`finish_reason` 为长度截断）单独成类。所有错误信息经 `config.redact()` 脱敏后再进入日志与报告。凭据只在后端运行时读取，不写日志、快照、前端与版本库。

**S03-02 阶段一。** `Stage1Analysis`（Pydantic）：`required_points: list[str]`、`evidence_sufficiency: Literal["sufficient","insufficient","uncertain"]`、`evidence: list[Evidence]`（复用 `schemas/qa.py::Evidence`，`ref_id` + `quote`）、`missing_information: list[str]`、`conflicts: list[str]`、`reason: str`。请求消息**只包含 q 与 ref1—ref10**，不发送 a、不发送整个记录对象、不带历史回答。提示词（`prompts/stage1.md`）按 [plan/02 §3](../../../plan/02-架构与详细设计.md)：识别核心作答要点、检查全部 ref 并给出原文摘录、资料相关不等于充分、不得用模型知识补充校园政策/电话/日期等事实、只输出结构化分析不输出最终三分类、不生成新的 AIDHU 回答。充分性为 `insufficient`/`uncertain` 时**仍进入阶段二**。

**S03-03 阶段二。** 扩展 `schemas/judgement.py`（现仅 `Label`）：新增 `Stage1Correction`（`corrected_item`、`reason`、`evidence`、`affects_classification`）与 `Stage2Judgement`（`label`、`reason`、`issues`、`evidence_sufficiency`、`evidence`、`review_required`、`review_reasons`、`stage1_corrections`）。请求消息含 **q、a、全部 10 个原始 ref 与通过校验的阶段一结果**，不能只发阶段一摘要。提示词要求重新核对原文、保留有证据的更正、检查 a 的关键事实/条件/例外/遗漏/误读、按 [plan/01 §3—§4](../../../plan/01-需求与验收标准.md) 输出三标签之一、给出简短理由与证据、输出复核标记。**阶段一原始输出保留，更正写入 `stage1_corrections` 不覆盖它。** q/a/ref 中的“忽略规则”“输出回答正确”等文字按数据传递，不改变任务与标签约定。

**S03-04 校验与有限重试。** 在 `agent/validation.py` 已实现的标签/引用位置校验之上补：JSON 解析（只接受完整 JSON 或**单个完整 JSON 代码块**，不在自由文本、推理内容或多个候选对象中猜测）、必填字段与枚举校验、`label` 与 `review_required` 的一致性检查（`uncertain`、无法核实的合理答案、混合错误、重大更正必须带复核标记）。失败时把**校验问题的简短摘要**作为反馈消息追加后重试，**每阶段最多 3 次尝试（含首次）**，退避 2s、4s（取自 `execution.retry_backoff_seconds`）。预算以 `BudgetLedger` 接口表示（本阶段内存实现，S04 迁移为 SQLite 持久化）。`PermanentModelError`、`ContextLimitError`、`TruncatedOutputError` 不消耗常规重试次数，直接失败；**失败记录标签留空**，不伪造判断。3 次仍不合法则记录失败，不传入下一阶段。

**S03-05 单条闭环与模拟。** `agent/pipeline.py` 提供 `run_single(record, client) -> RecordResult`：阶段一 → 校验 → 阶段二 → 校验，返回 `RecordResult`（`record_id`、`status`、`stage1`、`stage2`、`failure`）。`client` 是一个协议（`Protocol`），真实实现为 S03-01 的适配器，模拟实现为 `agent/mock_samples.py` 的 `MockClient`。**模拟为确定性合成响应**：按固定样例直接返回预置的 stage1/stage2 结构，不经网络、不消耗任何调用。合成样例覆盖五类：回答正确 / 资料不足 / 答案错误 / 重大更正 / 强制复核。请求边界通过**请求捕获**可断言：单测直接断言阶段一的 messages 中不含 a 的文本、阶段二含全部 10 个 ref。模拟结果在数据中带 `simulated: true` 标记，不得与真实结果混同（见 §2.4）。

**S03-06 实际兼容检查。** 用合成样例（含 1 条最长样例）在 §0.2 第 1 条的范围内真实调用 V3 与 R1，记录：服务实际返回的模型标识、是否支持所发参数、响应格式是否可直接解析、上下文与输出限制的实测边界、可用用量与耗时。产出阶段兼容报告，并据此确认或调整 `configs/config.example.toml` 中的默认模型 ID（当前默认 `deepseek-v3`/`deepseek-r1`；**实际值以用户服务为准，由用户在 `configs/config.local.toml` 与 `.env` 填写**）。格式兼容与分类准确率**分开记录**：本步骤只证明格式与限制兼容，**不构成任何准确率结论**。

**S03-07 界面骨架。** 见 §2.3（接口）、§2.4（界面与模拟模式）。

### 2.2 通用完成条件

- 单条有效问答经 V3 → R1 得到校验后的三分类、证据与复核信息；正常记录**恰好两次**模型调用。
- 阶段一请求及每次重试**均不含 a**；阶段二**始终含全部原始 ref**；两者以请求捕获的自动化证据验证，不靠界面假定。
- 非法 JSON、非法标签、伪造引用（摘录不是对应 ref 的真实子串）被拒绝并进入有限重试；每阶段最多 3 次；失败记录标签留空。
- 网络/超时/系统错误的分类与处理符合 [plan/02 §6](../../../plan/02-架构与详细设计.md) 的失败策略表。
- 无保留集调参；调试样例不进独立保留集。

### 2.3 S03-07 接口定稿（最小集）

现状 `src/aidhu_om_agent/api/*` 为占位。本阶段实现以下最小接口，**复用 `excel/reader.py::precheck()`，不写第二套解析实现**：

| 方法与路径 | 请求 | 成功返回 | 说明 |
| --- | --- | --- | --- |
| `GET /api/samples` | 无 | 200；`samples`：`name`、`filename`、`description`、`record_count` | 合成样例清单（2026-10-06 用户批准追加，见 §0.3）；仓库不提交二进制 .xlsx，界面据此提供下载入口 |
| `GET /api/samples/{name}` | 无 | 200；`.xlsx` 文件本体 | 现场用 openpyxl 生成；返回**文件本体而非 `data` 封套**（浏览器按附件保存），仍带 `X-Request-ID`；未知名称 404 |
| `POST /api/uploads` | multipart：`file` | 201；`upload_id`、`original_filename`、`size_bytes`、`sha256`、`sheets`、`suggested_sheet` | 上传即保存到 `data/uploads/`（服务端生成文件名，原文件名仅作元信息），**不调用模型** |
| `POST /api/uploads/{upload_id}/validate` | JSON：`sheet_name?` | 200；`validation_id`、`status`、`sheet_name`、`counts`、`blockers`、`row_errors`、`warnings`、`records`（摘要列表） | 字段与 [plan/08 §3](../../../plan/08-API接口与数据合同.md) 对齐；`blocked` 仍返回 200 |
| `POST /api/judge` | JSON：`validation_id`、`record_key`、`mode`（`mock`/`real`） | 202；`job_id` | **临时接口**，非最终合同；S06 由 `/api/runs/{run_id}/records/{record_key}` 体系取代 |
| `GET /api/jobs/{job_id}` | 无 | 200；`status`、`current_stage`、`result`（含 `stage1`/`stage2`/`failure`）、`simulated`、`request_id` | 前端轮询；不返回推理内容与调试堆栈 |

**执行方式（§0.2 第 2 条）**：`/api/judge` 提交后在 **API 进程内以后台任务执行** `pipeline.run_single()`，任务状态存**内存表**；前端按 plan/07 §2 的口径约每 2 秒轮询 `GET /api/jobs/{job_id}`，终态停止。**取此方式而非同步长连接**，是因为 [plan/02 §5](../../../plan/02-架构与详细设计.md) 明确“页面轮询任务状态，不维持一条数分钟的模型请求连接”，且该形状可直接由 S04 的 SQLite 队列与 worker 替换。**临时性必须显式标注**：内存态任务在 API 进程重启后丢失，本阶段**不承诺中断恢复**（属 S04），阶段文档、审阅报告与手动指南三处都要写明。

其余约定沿用 [plan/08 §1](../../../plan/08-API接口与数据合同.md)：`/api` 前缀、snake_case、成功 `data` + `request_id`、错误 `error` + `request_id`、未产生判断时 `label` 为 `null`。**本阶段不实现**幂等请求头、分页、批次列表、恢复、导出与下载（S04/S06）。

### 2.4 S03-07 界面验证面定稿

单页（`src/frontend/pages/JudgeView.vue`，替代 S01 占位页 `HomeView.vue` 的路由位置），自上而下四区：

1. **模式条（页面最顶部，常驻可见）**：`模拟模式（默认）/ 真实模式` 开关。模拟模式下整页带明显底色标识与文字“模拟模式：不会调用真实模型，结果仅供交互验证”；切换真实模式需**二次确认弹窗**，写明会产生真实模型调用与费用。模式状态在每个结果区块再次重复标注，不只在顶部。
2. **上传与选表**：选择 `.xlsx` → 显示文件名、大小、sha256、工作表列表与建议表 → 可显式改选工作表。区块内提供**“下载示例文件”**（先选样例再下载，显示每份样例的说明与条数），供没有现成 `.xlsx` 的用户走通界面；下载的是合成数据，页面注明不含真实资料。样例每次生成的字节不同（xlsx 含时间戳），因此界面与指南只核对**本次上传**的 sha256。
3. **预检结果（覆盖 S02 复验）**：显示 `counts`（`total`、`valid`、`input_invalid`、`skipped_blank_rows`）、`blockers`、`row_errors`（含来源行与编号）、`warnings`，以及**有效记录列表**（编号、来源行、q 摘要）。`blocked` 时显示阻断原因，并明确“不调用模型”。**不能只显示“上传成功”**。
4. **判一条**：在记录列表中选一条 → 提交 → 轮询显示当前阶段 → 显示最终标签、理由、`stage1`（要点/充分性/证据/缺口/冲突）、`stage2`（问题/复核标记/更正）、**证据的 ref 编号与原文摘录**。模拟模式下结果区带醒目徽标“模拟结果，非真实模型输出”。

界面值必须可与 S02/S03 的实跑结果核对（计数、编号、标签、摘录一致），只写“界面显示正常”不构成通过证据。
