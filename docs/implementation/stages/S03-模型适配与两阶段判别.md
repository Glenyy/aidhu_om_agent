## 1. 阶段目标与边界

单条有效问答可经 V3 → R1 得到校验后的三分类、证据和复核信息，实际服务兼容有记录。

本阶段不实现批量恢复或网页。阶段预算先提供执行器/账本接口，持久化到 S04；不能据此宣称中断恢复。调试使用独立样例或已指定校准集，不查看保留集预测调提示词。

## 3. 阶段完成条件

单条闭环与 JSON/原文校验通过；真实服务能力和限制有证据；未校验输出不作为最终标签；没有保留集调参。

步骤开发完成后自动执行以下审阅，保存 reviews/automated/S03/r01-自动化审阅.md。命令必须在实际开发时验证后填写；不能把尚未安装工具或未实现测试标为通过。

- 模拟核对阶段一请求及每次重试均不含 a，阶段二始终含全部原 ref。
- 覆盖正确、资料不足、答案错误、重大更正与强制复核；失败标签留空。
- 检查非法输出、伪造引用、网络/超时/系统错误、每阶段预算及 SDK 重试。
- 实际兼容只在批准范围执行；格式兼容与分类准确率分开，不以模拟通过代替。

自动化审阅发现问题，在已批准范围内修复并复审；扩大范围前更新具体方案。报告通过后状态为“待手动审阅”，不代替用户接受。

## 4. 阶段结束需生成的手动操作审阅文档

自动化审阅通过后，根据真实实现生成 reviews/manual/S03/r01-手动操作审阅.md，写入版本、环境、准备数据、完整命令/点击、逐步预期和反馈记录。该阶段指南至少覆盖：

1. 运行已批准的三类独立单条样例，核对最终标签、理由与真实 ref 摘录。
2. 查看阶段一原结果和阶段二更正、复核标记，核查原始资料保留。
3. 用受控失败样例观察有限重试和空标签；查看实际模型兼容报告。

阶段一请求的 a 隔离以请求捕获自动化证据和审阅代码验证；不靠手动界面假定成立。实际服务样例必须标明调试用途，不进入独立保留集。
